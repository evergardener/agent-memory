# AM-Eval 第二十四轮：正式结果输入绑定门禁报告

## 1. 结论

第二十四轮修复了正式结果末端的可追溯性缺口：旧 CLI 在评分前会确认 run 文件 SHA，并读取所有 evidence
artifact 原始字节，但 `am-eval-result-v3` 输出只留下 `attestation.status=verified`，没有把实际 run 和
artifact 摘要写回结果。结果文件一旦单独流转，评审者无法从结果本身确定它评分了哪一份输入。

修复后：

- 输出升级为 `am-eval-result-v4`；
- JSON 与 Markdown 都携带正式输入来源；
- evaluator 必须收到实际 run 快照字节，不能只接收一个操作员填写的 SHA；
- run 字节、确认 SHA、解析对象和 canonical JSON 必须逐层一致；
- 重复 JSON 键、`true`/`1` 类型歧义和不同 run 字节均 fail-closed；
- 正式指标不更新，决定仍为 `INCOMPLETE`。

机器证据见
[`../benchmarks/am-eval-v1/round-24-formal-result-input-binding-gate.json`](../benchmarks/am-eval-v1/round-24-formal-result-input-binding-gate.json)。

## 2. 修复前复现

用现有正式 PASS 夹具执行旧 evaluator，得到：

```json
{
  "decision": "PASS",
  "result_schema": "am-eval-result-v3",
  "attestation_keys": ["schema_version", "status"],
  "has_input_run_sha256": false,
  "has_evidence_artifact_sha256s": false
}
```

虽然评分过程内部验证了输入，输出没有保留这些绑定，因此 `verified` 只是结论文字，不能独立定位原始
run 和 evidence files。

## 3. v4 输入合同

正式结果新增 `input_artifacts`：

```json
{
  "specification_file_sha256": "<official spec raw SHA>",
  "run_file_sha256": "<actual run file SHA>",
  "run_payload_sha256": "<verified canonical attested run SHA>",
  "evidence_sha256s": {
    "artifact-id": "<actual artifact bytes SHA>"
  }
}
```

CLI 使用安全文件快照读取 run，一次取得解析对象、原始字节和 SHA。正式 evaluator 随后再次执行：

1. 确认值必须为 64 位 SHA-256；
2. 实际字节 SHA 必须等于确认值；
3. 原始字节必须是严格 UTF-8 JSON；
4. 每层对象禁止重复键；
5. 解析对象的 canonical JSON 字节必须与正在评分的 run 相同；
6. evidence 摘要从实际传入字节重新计算，不复制外层描述符。

`--format markdown` 也输出 execution reference、spec/run SHA 和逐项 evidence SHA，避免 Markdown 摘要
成为绕过来源记录的降级通道。

## 4. 攻击性回归

以下输入均被拒绝：

- 不传 run SHA；
- run SHA 与实际字节不一致；
- SHA 与字节一致，但字节解析为另一个 run；
- 把 dataset `blind=true` 的 JSON 字节替换为 `blind=1`；
- 在 run 顶层注入重复 `benchmark_id`。

最后两项专门覆盖 Python `True == 1` 和标准 JSON parser 默认接受重复键造成的跨解析器歧义。

- AM-Eval 测试：277/277；
- 非 integration 后端测试：533/533，另有 46 项 integration 本轮未重复执行；
- actual benchmark CLI result binding：PASS；

- 前端测试：6/6；

- `git diff --check`：PASS。

Review 确认 formal run 必须有非空、exact-set 的 evidence artifacts，因此 v4 不会为正式结果静默输出空
artifact map；legacy run 的 `input_artifacts=null`，同时仍只能得到 `ATTESTATION_REQUIRED`，不会成为
release-ready。

## 6. 保留边界

本轮让结果绑定其直接输入，但结果文件自身若在输出后被修改，仍需外部不可变存储、签名或 artifact
attestation 检测。GHCR manifest 的远端 provenance 也仍是独立执行证据，不能由本轮摘要替代。

本轮没有启动数据库、API、worker，没有调用外部模型，没有读取记忆正文，也没有连接或修改生产环境。
M01、M02、M03、M07、M22、M23 仍未完成正式测量，`release_ready=false`。
