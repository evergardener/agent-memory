## 1. Review 发现

execution plan v3 已冻结模型名称、API base、调用预算、事实提取上限和 turn allowlist，但仍有四类
运行时输入可能在 plan 审核后漂移：模型超时、Current/Weather 时间窗口、可信观察工具 allowlist，以及
隔离数据库的 Alembic schema revision。

这些输入会改变请求是否超时、事实类型和有效期判断、工具结果能否作为证据，以及 runner 实际执行的
SQL 结构。同一个 plan 如果允许这些输入变化，M01、M02、M03、M22 和 M23 的结果就不能可靠比较。

## 2. execution plan v4

本轮将 plan 升级为 `am-eval-atomic-execution-plan-v4`，runner 升级为
`am-eval-atomic-runner-v4`，新增并冻结：

1. `model.timeout_seconds`；
2. `policy.current_state_days`；
3. `policy.weather_state_hours`；
4. `policy.trusted_observation_tools`，以去重、排序、casefold 后的规范列表保存；
5. `policy.atomic_extraction_version`；
6. `database.schema_revision`，当前为 `0019_review_queue_indexes`。

preflight 要求四项环境配置与 plan 精确相等。正式 runner 连接隔离数据库后的第一个操作是只读查询
`alembic_version`；schema 不一致时在创建 namespace、写入 evidence 或调用模型前失败关闭。源码测试还
要求 runner 常量与迁移目录的唯一 head 相同，避免新增迁移后忘记升级 plan schema 绑定。

## 4. Review 结论与剩余风险

本轮未发现阻断提交的问题。execution plan 已覆盖当前直接影响原子事实 runner 行为的 Settings 和数据库
schema，且现有公开合成数据可以在同一配置上重复执行。

仍需单独加固的可重复性边界是：`system_version` 与 `system_revision` 当前由计划创建者显式填写并纳入
SHA 审核，但 runner 尚未用构建期只读身份来源再次证明它们与正在执行的代码完全一致。后续可将镜像 OCI
revision 或源码 checkout HEAD 作为独立运行时证明；该项不影响本轮配置漂移修复，也不授权真实模型运行。
