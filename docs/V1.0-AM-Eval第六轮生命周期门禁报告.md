## 4. 提交前 review 修复

review 发现并关闭了以下误放行或泄漏风险：

1. 将运行时 Python `assert` 全部改为显式失败检查，`python -O` 下 invariant 不会被优化掉；
2. runner 入口本身复验完整 20-case 覆盖，空 case 不能返回 PASS；
3. 固定官方 JSONL SHA 和 manifest 结构，不能对篡改数据重新计算 SHA 后继续冒充同一 dataset ID；
4. 数据库 URL 只从环境读取，避免凭据出现在命令行进程列表；
5. CLI 在数据库连接前拒绝仓库内输出、非 loopback 主机和非 `am_eval_` 数据库；
6. runner 在任何写入前拒绝非自动化 namespace 和已有 namespace 的数据库；
7. 失败结果只记录 case ID、action 与错误类型，不保存测试正文或连接信息；
8. purge API 与 Gate 共用精确确认 ID 契约，并保留既有 API 集成覆盖。

本轮未发现新增的高风险代码漏洞。公开合成数据不含生产正文；扫描命中的 password/secret 仅为
测试专用占位值或文档占位符。
