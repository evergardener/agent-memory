## 1. 本轮目标与结论

第七轮完成了评测 key 文件安全门禁，但当时的 metadata-only plan 只输出到终端，正式 runner 仍从
命令行分别接收模型、端点、revision 和调用预算。这些重复输入允许计划审核后发生配置漂移，也无法让
结果、质量评分和效率评分证明自己来自同一个已审核计划。

第八轮将运行契约升级为仓库外的 `0600` execution plan，并加入零网络、零数据库连接 preflight。
提交后的完整非集成回归和 loopback CLI Gate 均通过，execution plan SHA 已贯穿 runner 输出、质量
结果、效率输入、效率结果和终端摘要。当前工具链已具备执行真实公开合成 shakedown 的配置闭合能力，
但尚未获得外发确认，也没有非生产 key，因此没有启动供应商调用。

## 2. 冻结执行计划

`am-eval-atomic-execution-plan-v2` 固定：

1. dataset ID、manifest SHA、可见性和生产派生数据声明；
2. 自动化 namespace、run ID、Git revision 和系统版本；
3. 模型名、无凭据 API base、精确调用预算、零重试和禁止 backfill；
4. case 数、最大原子事实数和完整 turn allowlist；
5. 与数据类别匹配的外发确认口令。

plan 必须在源码仓库外由 `agent-memory-plan-atomic-benchmark` 以 `0600` 创建。runner 只接收 plan 路径
和人工确认 SHA，不再提供可覆盖上述字段的重复参数。plan 文件的符号链接、硬链接、宽权限、超限大小、
SHA 漂移或 schema 漂移都会在数据库连接前失败关闭。

## 3. 零网络 preflight

`agent-memory-preflight-atomic-benchmark` 会验证：

- manifest 与 plan 的逐项绑定；
- loopback `am_eval_` 数据库 URL 的格式，但不建立连接；
- 环境变量与 plan 的模型、端点、namespace、SHA、allowlist 和事实数限制；
- key 与输出路径的权限、链接、范围和大小；
- 外部公开合成运行只能使用固定的官方 24-case open dataset。

测试将数据库端口明确设置为不可达的 `127.0.0.1:9`，preflight 仍返回 `PREFLIGHT_PASS`；同时确认
模型调用数为 0、外发为 false，且没有生成预测或效率输出。该结果只证明配置闭合，不构成外发授权。

## 4. Key 使用链路 review

本轮 review 发现：原先 preflight 虽通过受限文件描述符读取 key，但正式 worker 会再次从配置路径打开
key 文件，形成一次未受同等约束的二次读取。修复后，runner 把同一个已验证 `ModelProfile` 显式传给
模型任务；worker 不再按路径重新读取评测 key。

同时新增以下限制：

- key 文件大小上限 16 KiB；
- key 必须是单行、无任意空白字符的非空值；
- API base 禁止用户名、密码、query 和 fragment，避免凭据进入 plan；
- plan 文件大小上限 1 MiB；
- 文件打开前后校验 inode、普通文件类型、链接数量和权限。

## 6. 证据链与剩余 Gate

正式 runner 输出升级为 `am-eval-atomic-output-v2`，并要求以下产物具有同一个
`execution_plan_sha256`：

- 原始 atomic output；
- quality result；
- efficiency input 与 result；
- 终端完成或失败摘要。

质量评分和 isolated efficiency 评分还必须显式传入 `--confirm-plan-sha256`，不匹配即拒绝。下一步
真实公开合成运行仍需：仓库外 `0700/0600` 非生产 key、人工审核 plan 和 SHA，以及独立提供
`SEND_SYNTHETIC_BENCHMARK_TO_EXTERNAL_MODEL`。私有 blind 数据和生产 M22 shadow 不在该授权范围内。
