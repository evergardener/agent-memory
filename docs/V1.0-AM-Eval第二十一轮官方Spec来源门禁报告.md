# AM-Eval 第二十一轮：官方 Spec 来源门禁报告

## 1. 结论

第二十一轮完成了正式评分规范和 artifact 来源类型的 fail-closed 加固。此前正式 scorer 会确认操作员
提供的 spec 文件 SHA，但没有证明该文件就是冻结的官方 `am-eval-v1/spec.json`；同时旧通用
`am-eval-measurement-attestation-v1` 没有 typed source-result validator。

修复后：

- 正式评分只接受登记的 `am-eval-v1` 官方规范；
- 同时核对原始文件 SHA 与规范化语义 SHA；
- 任何权重、门槛、required 标记或 measurement 定义漂移都会拒绝；
- 旧通用 measurement attestation 从正式白名单移除；
- 正式结果升级为 `am-eval-result-v3`，直接携带两个 spec 摘要；
- 本轮不更新正式指标，决定仍为 `INCOMPLETE`。

机器证据见
[`../benchmarks/am-eval-v1/round-21-official-spec-provenance-gate.json`](../benchmarks/am-eval-v1/round-21-official-spec-provenance-gate.json)。

## 2. 风险复现

### 2.1 任意自确认 spec

旧逻辑只比较“实际 spec 文件 SHA”和操作员传入的 `--confirm-spec-sha256`。如果操作员创建同样使用
`benchmark_id=am-eval-v1`、但删除 Gate 或降低门槛的文件，再确认这个新文件自己的 SHA，正式评分器
无法区分它与官方规范。这样可能在没有 10 个硬门禁和 23 个固定指标的情况下得到
`release_ready=true`。

### 2.2 通用 artifact 绕过 typed validator

旧通用 `am-eval-measurement-attestation-v1` 只检查测量值、通用 identity 和 producer 字符串，不内嵌也
不复核 lifecycle、recall、evidence、episode/procedure 或 reliability 的实际来源 ledger。虽然正式
assembler 不会生成该 schema，evaluator 的白名单仍允许手工构造它。

## 3. 修复契约

官方规范固定为：

- 原始文件 SHA-256：`a4ce9232ecafc37f9a3142a8e29020168af96aa6b4165e21fd64395186c7b679`；
- 规范化语义 SHA-256：`b25f605699051d7a611afbaeb9a31a0a6de46ef342b5a2be88b898b917f10a80`。

正式评分依次执行：

1. benchmark ID 必须在官方规范登记表中；
2. 操作员确认的原始文件 SHA 必须等于登记值；
3. 解析后的完整 JSON 使用稳定排序和紧凑编码重新摘要，必须等于登记语义 SHA；
4. 每个 measurement 必须由 quality、efficiency、lifecycle、recall、evidence、episode-procedure 或
   reliability typed artifact 唯一覆盖；
5. artifact 必须包含实际 source result bytes，且由各自 validator 从 ledger/计数重新推导测量值；
6. `am-eval-result-v3.specification` 记录两个规范摘要。

因此，单纯复制 producer 名称、重新计算自建 spec SHA 或重新签写 run payload 都不能绕过。

## 4. 攻击性回归

新增和保留的拒绝用例覆盖：

- 未登记 benchmark spec；
- 错误官方 spec 文件 SHA；
- 已登记 SHA 下的语义漂移；
- 官方仓库 spec 与代码登记摘要漂移；
- 旧通用 measurement artifact；
- 无 actual artifact bytes、artifact SHA 漂移、测量重写；
- fixture/oracle system、非真实模型 quality、非 blind/open quality 数据；
- scorer source/environment 和 exact OCI confirmation 漂移。

验证结果：

- AM-Eval 定向测试：271 passed；
- clean branch 跨主机交接：PASS；
- Python 非集成：527 passed，46 integration 正确跳过；
- 前端：6 tests、typecheck、production build 全通过；
- Ruff：PASS。

## 5. 边界与下一步

本轮只证明“正式评分规则不能被替换，测量必须来自 typed artifact”，不证明模型质量本身。第十九轮
10/10 硬门禁、17 项确定性指标、73% 覆盖的基线保持不变。

仍需新授权的正式工作：

1. 私有 blind gold 和真实外部模型运行，测量 M01、M02、M03、M07；
2. 真实模型 terminal-job 运行，测量 M23；
3. 生产 shadow 观察，测量 M22；
4. 创建 PR 后取得远端 image-contract 证据；不自动 merge 或部署。

本轮未创建数据库、API、worker 或临时凭据，未连接生产环境。
