## 1. 本轮选择与语义边界

第十三轮证明了质量和 M23 可以从 scorer 原始计数派生。本轮审计 G01–G10、M04–M21 后，没有创建
“通用手填证明”，而是选择已有冻结 JSONL、真实 repository 路径和明确 invariant 的 lifecycle runner。

生命周期结果只来源化它实际测量的五项：

| ID | 来源 | 复算方法 |
| --- | --- | --- |
| G05 | `current_hidden` 三个冻结 invariant | `3 - passed`，必须为 0 |
| G06 | `purge_residue_zero` | `1 - passed`，必须为 0 |
| M15 | 20 个 lifecycle case | `passed / 20` |
| M16 | 两个 purge case | `purge_passed / 2` |
| M17 | 六个 namespace-denied invariant | `passed / 6` |

G02 没有纳入：现有六个 namespace case 验证的是治理/状态操作被拒绝，不等同于“跨 namespace 越权召回
数”。M10、M20 也没有因为名称相近而强行映射。它们继续保持待专用 runner 来源化。

## 2. 实现结果

1. lifecycle CLI 改为一次安全 descriptor snapshot 同时计算 manifest SHA、解析 manifest 与 JSONL，且
   显式要求官方 manifest SHA。
2. lifecycle output 升级到 v2，记录 run id、dataset governance、source identity、Python/16 个关键依赖
   内容环境指纹；输出仍不含记忆正文。
3. formal lifecycle source 必须是 20/20 PASS、精确 action/invariant 计数、20 个唯一 PASS case，runner
   provenance 必须为 `image-build-metadata`。
4. `agent-memory-assemble-eval-attestation lifecycle` 生成 sourced lifecycle attestation v2，内嵌原始
   lifecycle result 字节及 SHA，并绑定 dataset、run、source/environment、OCI digest 与平台。
5. formal aggregator 只接受上述五项的精确覆盖；多一项、少一项、计数变化或 source 字节变化均失败关闭。
