# Agent Memory for Hermes — V1.0 统一经历与程序性记忆设计

> 冻结日期：2026-07-26。本文定义 `1.0.0-rc.8` 之后的核心能力目标。F1–F6 已在
> `codex/unified-memory-f1-f7` 隔离分支实现并通过客观 Gate；F7 用户主观验收和 F8
> 生产更新仍未完成。当前生产 canary 仍只具备 rc.8 能力，禁止把隔离分支能力宣称为
> 生产现状。

## 1. 目标与边界

Agent Memory 不是技术排障知识库，而是以本地用户为核心、由多个 Hermes profile
共同维护的个人长期记忆系统。它必须使用同一套证据和治理规则表达：

- 日常经历：旅行、见面、活动、第一次体验、生日和纪念日；
- 人物与关系：同学、朋友、协作者及关系随时间的变化；
- 兴趣与偏好：用户明确表达的喜好、约束、习惯及其演化；
- 协作经历：项目、排障、部署、迁移、决策、验证和变更报告；
- 可复用过程：由成功经历提炼出的、带条件和安全门控的程序性记忆。

V1 仍保持单用户、单 Hermes 产品和共享 namespace。各 profile 是不同人格和来源视角，
不是独立用户、独立数据库或互相隔离的事实世界。

## 2. 统一记忆形态

| 形态 | 回答的问题 | 典型内容 | 是否可以自动执行 |
| --- | --- | --- | --- |
| 情节记忆 | 何时、何地、谁经历了什么 | 成都旅行、生日聚会、一次 n8n 故障 | 否 |
| 语义记忆 | 当前或某段时间内什么成立 | 小 A 是大学同学、喜欢熊猫、MySQL 部署于 hostA | 否 |
| 程序性记忆 | 在什么条件下曾如何完成 | Next Terminal 回退流程、已验证排障顺序 | 否；只提供建议 |

同一份证据可以支持多种记忆形态，但不得因此复制原始证据。一次排障既是情节，也可能
更新服务拓扑事实，并在验证成功后为程序性记忆提供支撑。一次旅行既是情节，也可能产生
“去过成都”的长期事实；仅凭“看过熊猫”不得推断“喜欢熊猫”。

## 3. 来源、主体和参与角色

每条记忆必须分开保存：

- **记录来源**：由哪个 `source_profile`、实例、会话和回合提供证据；
- **经历主体**：现实中经历、执行或拥有该信息的 Subject；
- **参与实体**：人物、地点、服务、设备、组织、概念或知识制品；
- **叙事视角**：用户陈述、工具观察、profile 执行、人工更正或多证据归纳。

`source_profile=qishuo` 只说明 qishuo 收到了或记录了信息，不能自动推出 qishuo
参加了成都旅行。若 qishuo 实际执行了容器排障，则 qishuo 可以同时是记录来源和执行主体。

主体与实体的角色至少支持：

- `actor`：执行动作；
- `experiencer`：经历事件；
- `participant`：参与事件；
- `subject`：长期事实或偏好的所属主体；
- `location`：事件地点；
- `object`：动作对象；
- `affected`：受事件影响的服务、设备或人物；
- `artifact`：报告、知识库记录、照片说明等支撑制品。

## 4. 时间语义

### 4.1 时间不是默认行星

普通日期、时间戳和时长是情节属性、时间索引和星图时间标记，不生成 canonical entity。
系统必须支持：

- 单一发生时间；
- 开始—结束时间范围；
- 只知道日期、不知道具体时刻；
- 用户所在时区和原始时区；
- 相对时间解析及解析依据；
- 未确认、模糊或冲突时间；
- 跨日、跨时区事件。

“7 月 10 日至 7 月 11 日去了成都”应保存为一次情节的时间范围，而不是创建两颗日期行星。

### 4.2 生日、纪念日和重复时间

生日和纪念日是可重复的长期时间规则，不只是过去的一次事件。至少保存：

- 所属 Subject/entity；
- 月、日和可选年份；
- 时区；
- 重复规则；
- 名称与类型；
- 来源事实和确认状态；
- 敏感等级；
- 是否允许提醒、提前量和渠道策略。

“记住日期”和“允许主动提醒”必须分开授权。未启用提醒时只参与显式或高相关召回，不得
由互动状态模块自行外发消息。

## 5. 多实体时间情节

### 5.1 情节最小结构

一个 episode 至少应包含：

- `episode_type`：旅行、相遇、纪念日、项目、故障、部署、迁移、日常活动等；
- `started_at`、`ended_at`、`time_precision`、`timezone`；
- 主体、参与实体及其角色；
- 地点和主题；
- 有顺序的子事件或步骤；
- 结果、未决项和重要程度；
- 支撑事实、证据和人工治理记录；
- `candidate|active|superseded|forgotten|isolated` 生命周期；
- 抽取方法、版本和置信度。

情节边界由时间、主题、参与实体和会话信号共同确定，不能简单地把某个实体的全部阶段事实
永久合并成一个 episode。

### 5.2 情节步骤

情节步骤用于表达有顺序的经历，不限于技术过程。步骤类型至少包括：

- `observation`：看到、听到或由工具观察到；
- `action`：主体执行的动作；
- `encounter`：与人物或对象相遇；
- `decision`：明确决定；
- `hypothesis`：尚未验证的判断；
- `result`：动作结果；
- `cause`：经证据确认的原因；
- `resolution`：解决或完成；
- `verification`：结果验证；
- `milestone`：第一次、生日、纪念日等里程碑。

顺序只表达已知先后。`caused_by`、`ruled_out_by`、`resolved_by` 等因果边必须有明确证据，
不能从时间相邻或共同出现中推断。

## 6. 长期事实、人物关系和偏好演化

### 6.1 长期语义

从情节派生长期事实时必须保留 `valid_from`、`valid_to` 和来源。例如：

- `Evergarden --classmate_of--> 小 A`；
- `Evergarden --has_visited--> 成都`；
- `MySQL --deployed_on--> hostA`；
- `jiuyue --performed--> 某次部署`。

事件性关系和长期关系不得混淆。“在成都遇到小 A”是事件步骤；“小 A 是大学同学”是
长期人物关系。

### 6.2 偏好准入

偏好遵循以下优先级：

1. 用户明确表达的偏好或约束可以进入长期事实；
2. 用户明确修正优先于旧偏好，并保留版本和生效时间；
3. 多次行为只能形成待确认候选，不能直接推断心理偏好；
4. 单次经历、情绪或购买行为不得自动等同于长期喜好；
5. profile 的表达风格不能写成用户偏好。

偏好可包含主题、倾向、强度、适用范围、来源、显式程度和有效期。偏好变化使用替代链，
不得用新结论覆盖历史。

## 7. 程序性记忆

程序性记忆只能由一个或多个有结果、有验证、可追溯的情节提炼。最小结构包括：

- 适用对象和环境条件；
- 触发症状或目标；
- 有序步骤和分支；
- 每一步的预期观察；
- 成功、失败和停止条件；
- 风险级别、所需权限和人工确认点；
- 支撑 episode、fact、evidence 和变更报告；
- 版本、适用时间及被替代关系。

程序性记忆是“过去验证过的处理建议”，不是执行授权。Hermes 在复用前必须检查当前环境，
不得盲目重放旧命令、使用旧凭据或跳过破坏性操作审批。

## 8. 抽取、整理和准入流程

```text
只读证据
  → 原子事实与实体提及
  → 主体/参与角色与时间解析
  → 候选多实体情节
  → 人工或规则准入
  → 长期关系、偏好、重复时间规则
  → 多情节长期脉络
  → 经验证情节提炼程序性记忆
```

准入规则：

- 明确用户陈述可作为事实证据，但事件边界、人物同一性和偏好推断仍须分别评估；
- profile 回复只有得到用户确认、工具验证或其他证据支持后才能提升；
- 不可信工具结果保留证据并进入治理队列，不自动成为稳定事实；
- 模型只生成候选结构；所有关键字段必须绑定逐字证据、事实或人工操作；
- 低置信、冲突、敏感或缺少主体/时间的内容停留在候选状态；
- 候选治理必须支持确认、修正、忘记、脱离和永久清除，不能只有移除路径。

## 9. 召回与 Hermes 使用方式

召回除词法、语义和实体关系候选外，还必须支持时间和程序候选：

- 人物、地点、日期、事件类型和 Subject 的组合查询；
- “去年去成都做了什么”“什么时候第一次看熊猫”等时间情节查询；
- “小 A 是谁”返回人物关系和相关情节，而不是无预算展开全部历史；
- “再次出现数据库连接失败”先返回相似情节、当时环境、根因、验证和报告；
- “如何通过 Next Terminal 连接”返回适用的程序版本、分支和安全门控。

Hermes 默认得到紧凑摘要和证据引用。只有在明确追问、复盘或执行计划时才展开完整时间线或
程序步骤。召回结果必须说明命中渠道、适用条件、时间、来源和是否已由用户确认。

## 10. 星图投影

- 所有活跃 Subject 恒星参与同一个稳定多边形布局：1 个居中、2 个水平、3 个三角形、
  4 个方形、5–8 个正多边形，更多时使用稳定多环；布局不表达现实关系。
- Subject 对应 canonical entity 可以与行星建立有证据的语义边，但记录来源不得自动成为
  主体—行星关系。
- 情节作为临时星座，高亮主体、人物、地点、服务和制品，并显示时间范围和步骤时间线。
- 日期、事实句子、症状原文、命令和摘要不成为天体。
- 重复出现且具有独立语义的症状/根因概念可以成为概念行星；一次性错误原文只保留在证据中。
- 生日和纪念日使用时间环或日历标记；提醒授权不通过图形状态暗示。
- 程序性记忆以情节详情中的“已验证流程”展示，不把每个步骤生成行星。

## 11. 治理、安全和隐私

- 用户可确认候选情节、关系、偏好、纪念日和程序，也可逐字段修正；
- 对同一工具、来源或模式支持预览后的批量治理；批量操作必须可审计且不得默认物理删除；
- 涉及第三方人物的信息只保存完成用户记忆目标所需的最小内容；
- 生日、联系方式、精确位置等个人信息按敏感策略处理；是否进入普通召回由用户治理；
- 照片、文档和知识库报告默认保存引用、摘要和哈希，不把外部文件全文复制为普通事实；
- 所有派生对象随上游更正、忘记、脱离或清除重建；
- 备份恢复必须覆盖情节步骤、时间规则、偏好版本、程序及人工确认记录。

## 12. 冻结验收场景

### 12.1 成都旅行

输入：用户明确说明 7 月 10–11 日去了成都，遇到大学同学小 A，第一次去熊猫基地看熊猫。

必须：

- 形成一个时间范围明确的旅行 episode；
- User 为经历主体，记录该信息的 profile 仅为来源；
- 成都、小 A、熊猫基地和熊猫为参与实体；
- “大学同学”可成为有证据的长期关系；
- “第一次去熊猫基地”为里程碑；
- 不自动推断用户喜欢熊猫；
- 可按日期、地点、人物和“第一次”召回并追溯证据。

### 12.2 生日与纪念日

必须保存重复规则、主体、敏感等级和确认状态；未授权提醒时不得主动外发。日期被更正后旧规则
不再触发，但仍可追溯。

### 12.3 偏好与变化

明确“我喜欢安静的旅行”可成为长期偏好；单次安静旅行只形成候选信号。用户后续否定时建立
版本替代和生效时间，不能同时把相反偏好作为当前结论。

### 12.4 n8n 故障

必须形成包含症状、假设、动作、观察、根因、修复、验证和变更报告的有序情节。相似故障发生时
先召回该情节和当前环境差异，再提出步骤，不从头无差别排查，也不盲目执行旧命令。

### 12.5 Next Terminal

程序必须表达直接连接、交互式堡垒机回退、网络诊断、停止条件和权限门控。旧流程只有在当前
目标与环境条件匹配时才可推荐。

## 13. 兼容与迁移边界

- `1.0.0-rc.8` 的 evidence、fact、entity、relation、Subject 和治理记录保持不变；
- 现有 episode/arc 先视为 `legacy_derived`，迁移只增加新投影，不改写证据；
- 新表和索引必须可从空库迁移、从 rc.8 备份升级并可回滚到不使用新投影的代码；
- 首次重建只能在隔离副本上生成差异报告，经人工抽检后才允许在生产 namespace 启用；
- 模型保持默认关闭；确定性降级必须继续支持事实、时间和实体检索；
- 本设计不授权升级生产容器、启用模型、导入更多历史或改变 Hermes 配置。
