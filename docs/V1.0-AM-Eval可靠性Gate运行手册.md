# Agent Memory for Hermes — AM-Eval v1 可靠性 Gate 运行手册

## 1. 用途与边界

`agent-memory-run-reliability-benchmark` 使用两阶段协议测量 G07、G10、M18、M19、M20：

```text
prepare
  -> worker pending outage + expired lease recovery
  -> sequential + 8-way concurrent idempotency
  -> synthetic Vault entry + 47-table source snapshot
  -> private prepare receipt

external PostgreSQL service
  -> custom-format pg_dump
  -> restore into a distinct empty am_eval_ database

verify
  -> bind prepare SHA + dump SHA
  -> compare all table counts + migration revision + evidence hash + Vault ciphertext
  -> decrypt the same Vault entry in source and restored databases
  -> metadata-only final result
```

这是公开合成、非盲、无模型的确定性 Gate。它不读取生产数据，不使用生产 Vault key，也不替代生产
shadow 的 M22。prepare/verify 结果不保存事件正文、Vault 明文、数据库密码或 root key。

运行必须满足：

- source 与 restore PostgreSQL 都只使用 loopback 地址，库名均以 `am_eval_` 开头且彼此不同；
- source 迁移后必须没有 namespace；
- namespace 以 `hermes:automated-tests:` 开头；
- prepare、dump、result 和测试 Vault key 位于仓库外 0700 私有目录；
- 测试 key、数据库、容器内 dump 在退出时删除；
- 不启动或连接生产 API/worker，不调用模型，不读取外部 key。

## 2. 冻结数据集

- manifest：`benchmarks/am-eval-v1/datasets/reliability-gold-v1/manifest.json`
- manifest SHA-256：`e66d612909e010f6f95f2724d52b49b921cafcb135b836d2ceca1fa68cdc3490`
- case 文件 SHA-256：`1bb05791bc75c13bcd097e820fc4607cb27c338fb147124e30d6b29c30ff58ca`
- 5 条 metadata-only case：2 worker recovery、2 idempotency、1 backup restore；
- split：2 development、3 validation；
- 并发幂等尝试数固定为 8，顺序重放尝试数固定为 2；
- 恢复表集合固定为当前 47 个业务 base table。

加载器核验精确 case ID、scenario、attempt 数、invariant 集合、split、suite 与文件 SHA。新增或删除业务
表、修改 case 分母或把 dataset 标为含生产数据，都会失败关闭。

## 3. Prepare

首次 Python/uv 命令前设置仓库外私有 bytecode cache，并创建测试 Vault key：

```bash
PRIVATE='/absolute/private/path/am-eval-reliability-<run-id>'
mkdir -m 700 "$PRIVATE"
export PYTHONDONTWRITEBYTECODE=1
export PYTHONPYCACHEPREFIX="$PRIVATE/pycache"
mkdir -m 700 "$PYTHONPYCACHEPREFIX"
openssl rand -base64 -out "$PRIVATE/vault_root_key" 32
chmod 600 "$PRIVATE/vault_root_key"

SOURCE_DB='am_eval_reliability_source_<run-id>'
RESTORE_DB='am_eval_reliability_restore_<run-id>'
export AGENT_MEMORY_DATABASE_URL="postgresql://agent_memory:<isolated-password>@127.0.0.1:55438/$SOURCE_DB"
export AGENT_MEMORY_NAMESPACE='hermes:automated-tests:am-eval-reliability-<run-id>'
export AGENT_MEMORY_MODEL_ENABLED=false

uv run alembic upgrade head

uv run agent-memory-run-reliability-benchmark prepare \
  benchmarks/am-eval-v1/datasets/reliability-gold-v1/manifest.json \
  --confirm-sha256 e66d612909e010f6f95f2724d52b49b921cafcb135b836d2ceca1fa68cdc3490 \
  --database-url "$AGENT_MEMORY_DATABASE_URL" \
  --namespace "$AGENT_MEMORY_NAMESPACE" \
  --vault-root-key "$PRIVATE/vault_root_key" \
  --output "$PRIVATE/prepare.json"
```

prepare 通过条件：

| 来源 | 条件 |
| --- | ---: |
| worker outage | evidence hash 不变，原始 2 个 job 从 pending 到 done |
| expired lease | 回收精确 job，attempt 1 → 2，最终 done，evidence hash 不变 |
| sequential replay | 2 次尝试仅 1 个 winner、1 event、1 turn、2 job |
| concurrent replay | 8 次并发仅 1 个 winner、1 event、1 turn、2 job |
| Vault precheck | 合成条目可用测试 root key 解密 |

## 4. Dump、restore 与 Verify

使用 PostgreSQL 服务自身的 `pg_dump`/`pg_restore`，不要把 source 数据库改名充当恢复库：

```bash
PREPARE_SHA="$(shasum -a 256 "$PRIVATE/prepare.json" | awk '{print $1}')"

# 以下示例中的 postgres 是隔离测试 Compose service；不得换成生产 service。
docker compose exec -T postgres \
  pg_dump -U agent_memory -d "$SOURCE_DB" -Fc -f /tmp/am-eval-reliability.dump
docker compose cp postgres:/tmp/am-eval-reliability.dump "$PRIVATE/backup.dump"
chmod 600 "$PRIVATE/backup.dump"
BACKUP_SHA="$(shasum -a 256 "$PRIVATE/backup.dump" | awk '{print $1}')"

docker compose exec -T postgres createdb -U agent_memory "$RESTORE_DB"
docker compose exec -T postgres \
  pg_restore -U agent_memory -d "$RESTORE_DB" /tmp/am-eval-reliability.dump

uv run agent-memory-run-reliability-benchmark verify \
  --prepare "$PRIVATE/prepare.json" \
  --confirm-prepare-sha256 "$PREPARE_SHA" \
  --backup-artifact "$PRIVATE/backup.dump" \
  --confirm-backup-sha256 "$BACKUP_SHA" \
  --source-database-url "$AGENT_MEMORY_DATABASE_URL" \
  --restore-database-url "postgresql://agent_memory:<isolated-password>@127.0.0.1:55438/$RESTORE_DB" \
  --vault-root-key "$PRIVATE/vault_root_key" \
  --output "$PRIVATE/result.json"
```

verify 要求 custom-format `PGDMP` 魔数、prepare/dump SHA 显式确认、47 个业务表计数全等、Alembic
revision 全等、evidence ID+payload hash 摘要全等、Vault 密文字节摘要全等，且同一合成条目在 source
和 restore 中都能用相同测试 root key 解密。任一差异都会失败关闭。

## 5. 来源证明

只有在已验证镜像内按精确 OCI digest 运行的结果可组装正式来源证明：

```bash
RESULT_SHA="$(shasum -a 256 "$PRIVATE/result.json" | awk '{print $1}')"

uv run agent-memory-assemble-eval-attestation reliability \
  "$PRIVATE/result.json" \
  --confirm-source-sha256 "$RESULT_SHA" \
  --track deterministic-reliability \
  --image-reference 'ghcr.io/evergardener/agent-memory-api@sha256:<64-hex>' \
  --image-platform linux/arm64 \
  --output "$PRIVATE/reliability-attestation.json"
```

组装器从 worker、idempotency 与 restore ledger 复算 G07、G10、M18、M19、M20。操作员不能重填
结果或用旧 release-check 文本代替 source artifact。

## 6. 清理与审核

1. 删除 source/restore 两个 `am_eval_` 数据库并确认同名前缀残留为 0；
2. 删除容器内 dump 和测试 Vault key；
3. 确认 prepare、dump、result 均为 0600；
4. 保存三者 SHA、revision、source/environment SHA 与聚合计数；
5. 运行 Ruff、全量非集成测试、隔离 reliability DB pytest、uv lock 与 diff 检查；
6. 本地 clean-checkout 结果只用于诊断，正式 run 必须在 exact-digest 镜像内重跑。
