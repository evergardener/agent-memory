# AM-Eval 多数据集统一镜像 Gate 运行手册

## 1. 目的

本 Gate 把生命周期、召回、证据完整性、情节/程序和可靠性五类确定性来源证明统一到：

- 同一个自动化 run ID；
- 同一个系统 revision、source SHA 和运行环境指纹；
- 同一个精确 OCI manifest digest 与平台；
- 五个显式声明、互不混淆的冻结 dataset manifest；
- 一个 `am-eval-run-v3` / `am-eval-run-attestation-v2` 部分正式 run。

它覆盖 G01–G10 及 M04–M06、M08–M21。M01–M03、M07、M22、M23 不属于本 Gate，缺少这些
指标时最终决定必须保持 `INCOMPLETE`。

## 2. 安全边界

1. 只使用 `127.0.0.1` 上的隔离 PostgreSQL，数据库名必须以 `am_eval_` 开头。
2. recall API 不发布宿主端口；推荐与隔离 PostgreSQL 共享 container network namespace。
3. namespace 必须以 `hermes:automated-tests:` 开头。
4. 使用公开冻结合成数据；不得读取生产数据库、生产 namespace、生产 Vault key 或生产对话。
5. 所有输出置于仓库外 0700 目录，文件为 0600；原始结果、一次性 key 与 dump 不提交 Git。
6. 镜像必须按 digest 绑定；tag 只用于本机启动，不能写入正式 attestation。
7. 本 Gate 不授予外部模型调用、生产 shadow、生产容器升级或 PR/merge 权限。

## 3. 镜像前置 Gate

从干净 checkout 计算 source identity，构建单平台镜像并保存 BuildKit metadata：

```bash
python3 scripts/runtime-source-sha256.py --verify-clean-git --json

docker buildx build --load --platform linux/arm64 \
  --metadata-file "$PRIVATE/build-metadata.json" \
  --build-arg AGENT_MEMORY_BUILD_VERSION="$VERSION" \
  --build-arg AGENT_MEMORY_BUILD_REVISION="$REVISION" \
  --build-arg AGENT_MEMORY_BUILD_SOURCE_SHA256="$SOURCE_SHA" \
  --tag "agent-memory-eval:$REVISION" .

scripts/verify-image-build-identity.sh \
  "agent-memory-eval:$REVISION" "$VERSION" "$REVISION" "$SOURCE_SHA"
```

还必须确认默认 `/tmp/agent-memory-pycache` 为运行用户所有、0700 且为空。运行环境指纹允许 OCI
overlay 产生的只读硬链接，但仅限文件不属于当前运行用户且组/其他用户不可写；dataset 本身仍必须是
单链接普通文件。

## 5. 组装多数据集正式 run

```bash
agent-memory-assemble-deterministic-run \
  --artifact "lifecycle=$PRIVATE/lifecycle-attestation.json" \
  --artifact "recall=$PRIVATE/recall-attestation.json" \
  --artifact "evidence=$PRIVATE/evidence-attestation.json" \
  --artifact "episode-procedure=$PRIVATE/episode-procedure-attestation.json" \
  --artifact "reliability=$PRIVATE/reliability-attestation.json" \
  --benchmark-id am-eval-v1 \
  --confirm-run-id "$RUN_ID" \
  --confirm-track deterministic-composite \
  --confirm-image-reference "$IMAGE_REFERENCE" \
  --confirm-image-platform linux/arm64 \
  --output "$PRIVATE/deterministic-run.json"
```

组装器必须失败关闭于：缺少/多出 artifact kind、测量重叠或缺口、run ID/track/image/environment 不同、
dataset ID 或 manifest SHA 重复、operator confirmation 漂移。

`am-eval-run-v3` 使用按 ID 排序的 `datasets`；每个 sourced artifact 必须唯一匹配其中一个 manifest，
且每个声明 dataset 必须至少被一个 artifact 使用。旧的单数据集 `am-eval-run-v2` 继续兼容。

## 6. 镜像内正式聚合

必须在同一个精确镜像内、网络禁用、spec/run/artifact 只读挂载的条件下运行：

```bash
agent-memory-benchmark "$SPEC" "$PRIVATE/deterministic-run.json" \
  --confirm-spec-sha256 "$SPEC_SHA" \
  --confirm-run-sha256 "$RUN_SHA" \
  --confirm-image-reference "$IMAGE_REFERENCE" \
  --confirm-image-platform linux/arm64 \
  --artifact "lifecycle=$PRIVATE/lifecycle-attestation.json" \
  --artifact "recall=$PRIVATE/recall-attestation.json" \
  --artifact "evidence=$PRIVATE/evidence-attestation.json" \
  --artifact "episode-procedure=$PRIVATE/episode-procedure-attestation.json" \
  --artifact "reliability=$PRIVATE/reliability-attestation.json"
```

验收条件：

- attestation status 为 `verified`；
- G01–G10 全部 pass，无未测硬门禁；
- 17 个确定性指标 measured；
- coverage 为 73%；
- missing IDs 精确为 M01、M02、M03、M07、M22、M23；
- decision 为 `INCOMPLETE`，`release_ready=false`。

## 7. 清理

完成后停止并删除临时 API，精确删除本轮 `am_eval_` 数据库及一次性角色，删除 Vault key、dump 与原始
结果。机器证据只保留不含正文的 SHA、计数、Gate 状态和精确镜像身份。数据库残留必须为 0。
