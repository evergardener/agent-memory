worker 中断演练在 worker 停止后写入一条合成证据，确认当时为 `1` 条 evidence、`2` 个 pending job、
`0` 条事实；worker 重启后第一次轮询即恢复召回，返回 `1` 个 evidence source ID。

恢复演练使用 PostgreSQL custom dump 恢复到新数据库，比较 28 组核心表计数完全一致；源库和恢复库
均能用同一隔离 Vault 根密钥解密同一条测试密文。

## 7. 剩余缺口

当前最关键的未测项仍是模型介入后的真实记忆质量：

- M01 事实 precision；
- M02 事实 recall；
- M03 证据跨度准确率；
- M07 召回引用准确率；
- M22 真实对话分布下的人工治理率；
- M23 外部模型任务终态失败率。

这些指标不能从规则 fixture、表计数或过去生产观察中倒推。它们需要冻结的脱敏 Hermes 金标、严格
的 turn allowlist 和真实模型调用；对话正文、prompt/response 及凭据不得进入公开仓库。

## 8. 下一轮开发流程

1. 建立 100–150 条脱敏 Hermes 事实金标，按场景切分 development/validation/blind；
2. 增加标注契约：逐条 claim、精确 evidence span、实体/角色、生命周期及允许召回范围；
3. 在隔离 model-worker 中固定 `ocg/qwen3.7-plus`、prompt/policy 版本、turn allowlist 与预算，测
   M01/M02/M03/M07/M23；
4. 从只读生产 shadow 聚合候选/确认/脱离数量，测 M22；正文不写入评估结果；
5. 数据契约冻结后再实现 Honcho adapter，并使用完全相同的数据、模型与预算运行对照。

步骤 1、3、4 分别涉及真实数据、外部模型或生产只读 shadow，开始前仍需对应授权。第二轮不改变
生产 `canary_active` 状态，也不授权发布、合并 `main` 或部署。
