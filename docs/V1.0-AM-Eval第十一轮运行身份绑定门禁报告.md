## 1. 本轮解决的问题

第十轮已冻结模型、策略和数据库 schema，但 revision/version 仍可由计划创建者声明，尚不能证明正在
执行的代码就是该 revision。本轮把 execution plan 升级到 v5、runner 升级到 v5，并形成三段身份链：

1. Git checkout：清除继承的 `GIT_*` 重定向环境，核对 top-level 与完整 HEAD，拒绝
   assume-unchanged/skip-worktree，比较 HEAD blobs、checkout 源码和实际执行 package 的相同 canonical
   摘要，并在返回前重复核对 HEAD、index、status 和摘要；
2. Docker image：构建前从干净 checkout 计算 source SHA，non-editable wheel 安装后重新计算；只读
   `build-identity.json`、OCI labels 与镜像内实际运行 package 必须三方一致；
3. plan/output/scorer：plan 自动写入 revision/version/source SHA/file count；runner、质量评分器和
   isolated efficiency 评分器都重新解析完整 plan，并核对当前执行代码、输出身份和数据治理属性。

source SHA 的固定集合包括 `VERSION`、`alembic.ini`、`pyproject.toml`、`uv.lock`、Python migration 和
`src/agent_memory/**/*.py`。它证明 AM-Eval Python 运行源，不声称等于完整 OCI 文件系统；正式镜像运行
还应按 manifest digest 启动并记录 digest、SBOM、provenance 和 attestation。

## 2. Review 修复

三路独立 review 复现并推动修复了以下绕过路径：

- 恶意 `GIT_DIR/GIT_WORK_TREE/GIT_INDEX_FILE` 把脏 checkout 伪报为另一仓库的 clean HEAD；
- assume-unchanged/skip-worktree 隐藏已改 Python，或通过 ignore 规则增加未追踪运行源；
- non-editable site-packages 与 checkout 不同，却继续使用 checkout revision；
- 复用私有 pycache 中的 unchecked bytecode，在相同 `.py` 摘要下执行其他代码；
- scorer 只确认 64 位 SHA 字符串，不绑定 plan 的 revision/version/file count/model/policy；
- efficiency scorer 未完整校验 plan，伪造 database schema、重试和 backfill 仍可评分；
- 输出把生产派生数据伪报为 synthetic/open，评分结果继续传播错误治理属性；
- CI 与生产入口只看 OCI version/revision 标签，不读取 build identity 或重算运行包。

修复后提交前最终 review 未发现剩余可复现 P0/P1。字节码缓存必须为 runner 拥有、`0700`、位于源树
外并在进程启动前为空；本地评测使用一次性随机路径，镜像只在每个容器全新的 `/tmp` tmpfs 中使用固定
路径且禁止写 bytecode。

## 4. 生产与发布边界

CI 新增发布前单平台 image-contract；main 多架构发布后，对三个精确 SHA image 拉回并重复同一身份
验证。release/predeploy/production 启动脚本也在 `--no-build` 启动前验证外部 source SHA、OCI labels、
只读 build identity 和镜像内实际 package。两个新安全脚本已加入 deployment bundle 的关键文件集合。

这只是代码和自动化变更，没有执行生产升级。生产部署仍要求用户单独授权、恢复验证备份、精确 GHCR
digest/revision、canary 和来源策略 Gate；本轮授权不包含这些动作。

正式确定性基线仍为 `INCOMPLETE`：既有 10/10 硬门禁与 73% 权重覆盖率没有因本轮改变；真实模型
M01/M02/M03/M07、生产效率 M22/M23 仍未测，因此不更新正式分数。

2. 基于最终干净 revision 重新生成 plan v5，并人工审核模型、端点、24 次预算、turn allowlist、运行身份和
   plan SHA；

5. 只提交不含模型正文的聚合结果、任务终态和 Gate 证据。

production shadow 与私有 blind 数据仍分别需要新的授权，不能由 synthetic 确认隐式覆盖。
