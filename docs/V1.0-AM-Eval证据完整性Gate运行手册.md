# Agent Memory for Hermes — AM-Eval v1 证据完整性 Gate 运行手册

## 1. 用途与边界

`agent-memory-run-evidence-benchmark` 在全新隔离数据库中执行 9 条冻结的合成脱敏 probe，经真实
`ingest_turn` 路径持久化 event/redaction findings，再建立带 evidence 的 active fact 与 retrieval
document，并逐事实调用 `trace_memory`。它只测量：

- G01：event、fact、document 三类持久化面中的敏感明文泄漏数；
- G03：active fact 中没有 evidence link 的数量；
- G09：可通过 trace API 路径还原到精确 evidence event 的 active fact 比例。

这是公开合成回归 Gate，不是私有盲测或生产数据扫描。输入含项目自造的假密码、假 key 和格式化个人
标识 probe；没有真实凭据、Vault 值或生产消息。结果文件只保存 case ID、finding 类型计数、布尔值和
聚合计数，不保存输入或持久化正文。

运行必须满足：

- PostgreSQL 只使用 loopback 地址，数据库名以 `am_eval_` 开头；
- 运行前数据库没有任何 namespace；
- namespace 以 `hermes:automated-tests:` 开头；
- 输出位于源码仓库外 0700 私有目录，目标文件不存在；
- 不启动或连接生产 API/worker，不调用模型，不读取外部 key；
- 每次运行创建新数据库，结束后删除并确认无残留。

- manifest：`benchmarks/am-eval-v1/datasets/evidence-integrity-gold-v1/manifest.json`
- manifest SHA-256：`3734605eb7ad5cc3a491d46b97c96a63862594e24e15b487832cc59072310c18`

- case：9 条，5 development、4 validation；
- 持久化扫描面：每条 3 个，共 27 个；
- finding 类型：credential assignment、provider API key、AWS access key、private key header、CN ID；
- 另含一个已脱敏 placeholder fixed-point probe。

加载器核验完整 manifest/case SHA、精确 case ID、split、输入字段、forbidden fragment、finding 类型和
每条三个持久化面。当前 redaction 实现还必须与冻结 finding 序列一致，且输出再次脱敏时为 fixed point。

## 3. 隔离运行

首次 Python/uv 命令前配置仓库外私有 bytecode cache：

```bash
export PYTHONDONTWRITEBYTECODE=1
export PYTHONPYCACHEPREFIX='/absolute/private/path/evidence-pycache-<run-id>'
mkdir -m 700 "$PYTHONPYCACHEPREFIX"

export AGENT_MEMORY_DATABASE_URL='postgresql://agent_memory:<isolated-password>@127.0.0.1:55438/am_eval_evidence_<run-id>'
export AGENT_MEMORY_SERVICE_TOKEN='<random-test-token-at-least-16-chars>'
export AGENT_MEMORY_UI_SESSION_SECRET='<random-test-secret-at-least-32-chars>'

uv run alembic upgrade head

MANIFEST='benchmarks/am-eval-v1/datasets/evidence-integrity-gold-v1/manifest.json'
MANIFEST_SHA="$(shasum -a 256 "$MANIFEST" | awk '{print $1}')"

uv run agent-memory-run-evidence-benchmark \
  "$MANIFEST" \
  --namespace 'hermes:automated-tests:am-eval-evidence-<run-id>' \
  --output '/absolute/private/path/evidence-result.json' \
  --confirm-sha256 "$MANIFEST_SHA"
```

数据库密码和测试 token 只能从本机受限 secret 或进程环境读取，不能写入仓库或报告。

## 4. 原始 ledger 与通过条件

每条 case ledger 包含：

- 实际/预期 finding 类型计数；
- 持久化面数；
- 再次脱敏仍发现的敏感项数量；
- forbidden fragment 出现次数；
- 泄漏面数；
- active fact evidence link 与 trace 完整性布尔值。

通过必须同时满足：

| 项目 | 通过条件 |
| --- | ---: |
| case | 9/9 |
| 持久化面 | 27 |
| 敏感泄漏面 | 0/27 |
| active facts | 9 |
| 无 evidence active facts | 0/9 |
| trace 完整 | 9/9 |
| 独立 quality report | facts=9、traceable=9、raw sensitive=0 |

任一 finding 类型漂移、持久化面残留 probe、evidence link 丢失、trace 指向错误 event、独立聚合不一致或
数据库非空，runner 都失败关闭。结果写为 0600；`FAIL` 退出非零。

## 5. 来源证明

只有在已验证镜像内按精确 OCI digest 运行的结果可组装正式来源证明：

```bash
RESULT='/absolute/private/path/evidence-result.json'
RESULT_SHA="$(shasum -a 256 "$RESULT" | awk '{print $1}')"

uv run agent-memory-assemble-eval-attestation evidence \
  "$RESULT" \
  --confirm-source-sha256 "$RESULT_SHA" \
  --track deterministic-evidence \
  --image-reference 'ghcr.io/evergardener/agent-memory-api@sha256:<64-hex>' \
  --image-platform linux/arm64 \
  --output '/absolute/private/path/evidence-attestation.json'
```

组装器从原始 case ledger 复算：G01=`sensitive_leak_surfaces`/27，G03=`active_without_evidence`/9，
G09=`traceable_facts`/9。它还核验 dataset、独立 quality report、source/environment、原结果 SHA、OCI
digest 与平台，操作员不能重新填写数值。

## 6. 清理与审核

1. 删除 `am_eval_evidence_<run-id>` 数据库并确认同名前缀残留为 0；
2. 确认结果文件为 0600，且不存在冻结 probe、真实 secret 或数据库密码；
3. 保存 manifest/result SHA、revision、source/environment SHA 和聚合计数；
4. 运行 Ruff、全量非集成测试、隔离集成 Gate、uv lock 与 diff 检查；
5. 本地 clean-checkout 结果只用于诊断；正式 run 必须在 exact-digest 镜像内重跑。
