## 1. 本轮关闭的缺口

第十二轮已经要求 formal run 提交实际 artifact 字节，但旧 artifact 仍由组装者填写 `value` 与
`sample_count`。即使外层 SHA 完整，只要组装者同步重写 artifact 与 run，评分值仍可能脱离真实 scorer
结果。本轮把质量与效率证据继续下沉到评分器原始结果：正式 artifact 内嵌原始 JSON 字节、原始字节
SHA 和 schema，聚合器自己解码、校验并从原始计数复算指标。

这条链现在是：

```text
runner output / ledger
  -> quality v3 or efficiency v5 scorer result
  -> confirmed scorer-result SHA
  -> sourced attestation v2 with embedded original bytes
  -> formal run artifact SHA
  -> exact OCI name@sha256 + platform confirmation
  -> formal aggregation
```

操作员仍负责声明评测 track 和确认精确 OCI digest，但不能再重新填写 M01/M02/M03/M07/M23 的值。

## 2. 实现结果

1. 新增 `agent-memory-assemble-eval-attestation`。输入必须是单链接普通文件，并显式确认原始 scorer
   result SHA；输出必须位于仓库外 0700 私有目录，文件以 0600、`openat/O_EXCL/O_NOFOLLOW` 写入。
2. quality result 升级到 v3，增加 `dataset_blind` 与 `exact_spans`。组装器根据 predictions、gold、
   matched、exact spans、recall queries、correct citations 复算四个指标。
3. efficiency result 升级到 v5，保留原始治理与终态任务 `counts`，并绑定 dataset id、manifest SHA、
   visibility 与 blind 声明。组装器复算 M22/M23，但隔离证据只允许证明 M23；M22 仍必须来自另行授权的
   production-shadow 窗口。
4. sourced attestation v2 内嵌原 scorer 字节的 canonical base64、SHA 与 schema。任何一字节变化、重新
   填写 metrics、错误 plan/dataset/source/environment、失败任务或 checkout scorer 都会失败关闭。
5. formal 聚合器不再接受旧的 quality/efficiency attestation v1。质量证据必须是 private/restricted、
   blind、真实模型且属于 `recommended-product`；M23 必须来自完整终态任务账本。

## 4. 仍然不能宣布正式完成

本轮没有创建私有 blind 数据集，没有外部模型授权，也没有生产 shadow 观测。因此正式基线保持：

- 10/10 硬门禁；
- 73% 质量权重覆盖；
- M01/M02/M03/M07/M22/M23 未测；
- `decision=INCOMPLETE`，`release_ready=false`。

此外，G01–G10、M04–M21 的旧证据尚未全部迁移为“从各自 runner 原始计数派生”的 sourced adapter。
在这些 adapter 和 production-shadow M22 schema 完成前，不应开放新的完整正式 release decision。现有
M22 路径会因为缺少 production sourced artifact 保持不可完成，不允许用 isolated M22 替代。
