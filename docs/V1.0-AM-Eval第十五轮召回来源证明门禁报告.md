## 1. 本轮关闭的证据缺口

历史 G02、M05、M06、M08、M21 来自 pytest 断言和人工汇总；指标值正确不等于来源链完整。本轮新增
专用 recall runner，将冻结查询通过真实 loopback HTTP API 执行并产出 metadata-only ledger：

```text
frozen manifest + recall JSONL descriptor snapshot
  -> isolated empty PostgreSQL + loopback-only API
  -> 110 query ledger + 6 wrong-namespace ledger
  -> exact counters + inclusive p95
  -> embedded result bytes and SHA
  -> sourced recall attestation
  -> formal aggregate with exact OCI digest and platform binding
```

runner 输出不保存查询和事实正文，只保存 case ID、稳定 memory ID、前五名排序、布尔判定、HTTP 状态与
耗时，因此可复算且不会把公开合成记忆正文复制进 attestation。

## 2. 测量语义

| ID | 原始来源 | 复算方法 |
| --- | --- | --- |
| G02 | 6 个错误 namespace HTTP 请求 | 返回 memory ID 总数，且 6/6 必须为 403 |
| M05 | 10 个正样本的排名 | expected ID 位于第 1 位的数量 / 10 |
| M06 | 同 10 个正样本的前五名 | expected ID 位于前 5 的数量 / 10 |
| M08 | 100 个负样本 | 返回任意 memory ID 的数量 / 100 |
| M21 | 110 个正常 loopback HTTP 请求 | `statistics.quantiles(..., inclusive)[94]` |

G04 没有纳入：本轮只测 namespace 与召回排序，没有 profile 与现实主体标注，不能从同一 ledger 推断
主体混淆率。M07 仍属于私有 blind 质量 scorer 的引用证据指标，也没有被公开 recall suite 替代。

## 3. 实现与攻击回归

1. `agent-memory-run-recall-benchmark` 固定官方 manifest/recall SHA、case ID、正负样本和 split；只允许
   loopback API、`am_eval_` 数据库、自动化 namespace 和仓库外私有输出。
2. runner 在专用空库创建带 evidence 的合成目标事实与干扰项，经 API 执行 110 个正常请求和 6 个错误
   namespace 请求；正常请求必须 200，越权请求必须 403。
3. result exact schema 绑定 dataset governance、runner source/environment、完整 query/namespace ledger、
   原始计数和延迟边界，结果正文声明为 false。
4. recall attestation v1 内嵌原 result 字节及 SHA，从 ledger 复算五项测量，并绑定 exact OCI digest 与
   platform；formal aggregator 只接受五项完整覆盖。
5. 攻击测试证明：同步修改汇总计数、篡改 Top-1 布尔值、重写 p95、遗漏/重复 case、伪造返回 UUID、
   越权请求返回条目或非 403，都会失败关闭。
