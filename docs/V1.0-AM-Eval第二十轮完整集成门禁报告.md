## 3. 首次全量执行发现的问题

第一次全量 integration 执行得到 44 passed、2 failed。失败项分别是 episode/procedure 数据库 ledger
和 reliability prepare ledger。两者都明确要求专用空数据库，但测试代码直接使用全套共用的
`AGENT_MEMORY_DATABASE_URL`；前序 API/数据库用例写入 namespace 后，后序用例按设计 fail-closed。

这不是 runner 算法失败，而是测试隔离契约不可组合。修复方式：

1. 增加 loopback-only 的独立迁移数据库 fixture；
2. 每个相关用例创建随机数据库并执行 `alembic upgrade head`；
3. 用例结束后执行精确 `DROP DATABASE ... WITH (FORCE)`；
4. episode/procedure 与 reliability 均改用 fixture 返回的独立 URL；
5. 先定向验证 2/2，再在 clean Git 状态重跑全部 46 项。

修复提交：`a21a417 test: isolate database-dependent integration gates`。
