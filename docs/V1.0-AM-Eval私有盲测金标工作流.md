# Agent Memory for Hermes — AM-Eval v1 私有盲测金标工作流

- 状态：`TOOLING_READY / PRIVATE_DATA_NOT_CREATED`
- 数据位置：只能位于仓库外、权限为 0700 的私有目录
- 生产访问：工具不连接数据库、Hermes、容器或外部模型
- 外发：初始化、校验和冻结阶段均为 0

## 1. 目标与边界

本工作流建立 M01/M02/M03/M07 的第一版 Hermes 私有原子事实金标：

- 至少 50 个独立场景；
- 100–150 个逐字事实；
- 至少 200 个召回问题；
- 至少 100 个负样本；
- 按场景而非消息严格切分 development/validation/blind = 60/20/20；
- 每个 split 都覆盖生活经历、技术排障、偏好、时间、多 profile、工具冲突、程序安全和负样本攻击；
- development 至少含 50 个事实/100 个问题/50 个负样本，validation 和 blind 各至少含
  15 个事实/30 个问题/15 个负样本。

20 组 lifecycle 操作属于独立 Gate 数据层，不由本 atomic gold 工具生成，也不能用原子事实条数代替。
私有金标创建不授权读取生产；生产派生素材必须先在既定授权流程中人工选择、脱敏，再写入仓库外草稿。

## 2. 初始化私有工作区

父目录需事先存在；目标目录必须不存在且位于仓库外：

```bash
PRIVATE_GOLD_ROOT=/Users/evergarden/Data/current-documents/Projects/agent-memory-eval-private

uv run agent-memory-init-private-gold \
  "$PRIVATE_GOLD_ROOT/draft-v1" \
  --confirm CREATE_PRIVATE_GOLD_WORKSPACE
```

命令创建：

- `annotation-contract.json`：机器可读规模、切分和复核规则；
- `case-template.json`：只含合成占位内容的字段示例；
- `cases.draft.jsonl`：0600 空草稿。

工作区及文件不能移动到项目仓库。CI 会扫描 `benchmarks/`，一旦出现生产派生/private manifest 或
私有 annotation schema 立即失败。

## 3. 每条 case 的复核元数据

除 `am-eval-case-v1` 原子事实契约外，每条 case 必须带 `annotation`：

```json
{
  "schema_version": "am-eval-private-gold-annotation-v1",
  "scenario_id": "scenario-000001",
  "scenario_class": "technical_incident",
  "source_hmac_sha256": "REPLACE_WITH_64_HEX_PRIVATE_HMAC",
  "annotator_id_hash": "REPLACE_WITH_64_HEX_PRIVATE_HMAC",
  "reviewer_id_hash": "REPLACE_WITH_DIFFERENT_64_HEX_PRIVATE_HMAC",
  "annotated_at": "2026-08-12T08:00:00+08:00",
  "reviewed_at": "2026-08-12T09:00:00+08:00",
  "decision": "ACCEPT",
  "redaction_verified": true,
  "exact_span_verified": true,
  "semantic_verified": true,
  "used_for_tuning": false
}
```

`source_hmac_sha256`、`annotator_id_hash` 和 `reviewer_id_hash` 都应使用私有本地密钥产生 HMAC，且每条
case 的 source HMAC 必须唯一；
不得保存生产 session/turn/event UUID、用户名、profile、主机名或原始记录 ID。三个字段必须替换模板
占位值，并且通过 64 位十六进制非占位检查。annotator 与 reviewer 必须不同；复核时间不能早于标注时间。

`case_id`、`scenario_id`、evidence/fact/query ID 只允许固定前缀加纯数字序号，不得在 ID 里携带姓名、
profile、主机、日期或事件语义。初始化生成的三个重复字符 hash 是故意设置的无效占位值，未替换时校验必须失败。

同一 `scenario_id` 的改写、正例和负例必须全部属于同一 split。任何用于 prompt、规则、alias 或模型选择
的 case 必须标记 `used_for_tuning=true` 且只能放在 development；validation/blind 永久禁止调参使用。

## 4. 脱敏 Gate

自动扫描会拒绝：

- credential assignment、API Key、token、私钥等现有脱敏器命中；
- email、手机号、IPv4/IPv6、MAC 地址；
- Unix 用户/系统绝对路径以及 Windows 用户/系统路径；
- Bearer token 和 SSH 公钥；
- 非 `example.invalid` 的 HTTP(S) URL；
- 不符合官方纯序号格式的 case/scenario/evidence/fact/query ID。

`[REDACTED]` 和 `*.example.invalid` 可作为明确占位。自动扫描不能判断自然人姓名、罕见组织名或可关联的
事件组合，因此 `redaction_verified=true` 必须由独立 reviewer 人工确认，不能由工具自动填写。

校验命令只返回计数和错误类别，不回显正文：

```bash
uv run agent-memory-validate-private-gold \
  "$PRIVATE_GOLD_ROOT/draft-v1/cases.draft.jsonl"
```

只有返回 `READY_TO_FREEZE` 才能进入冻结。

## 5. 不可覆盖冻结

输出目录必须尚不存在：

```bash
uv run agent-memory-freeze-private-gold \
  "$PRIVATE_GOLD_ROOT/draft-v1/cases.draft.jsonl" \
  "$PRIVATE_GOLD_ROOT/frozen-v1" \
  --dataset-id private-hermes-atomic-gold-v1 \
  --confirm FREEZE_REDACTED_PRODUCTION_DERIVED_GOLD
```

冻结器按 split 写出三个 0600 JSONL，生成 manifest 和无正文 `freeze-summary.json`，再用公共 dataset
loader 重新验证每个 SHA、计数、exact span 和 case 覆盖。任一文件或目录已存在时拒绝覆盖。

manifest 固定：review contract、场景/事实/问题/负样本数量、60/20/20 场景计数、各 split 的事实/问题/
负样本计数、blind case 数和每个文件 SHA。runner 遇到 `contains_production_data=true` 时，还会确认
manifest 位于仓库外的 0700/0600 私有路径并重新计算这些值；手工伪造 private manifest、
删除 annotation 或改变正文都会在任何模型调用前失败。

## 6. 后续授权

冻结成功只说明私有数据满足本地评测契约，不自动允许外发。真实 blind 运行前仍需单独确认：

1. 指定外部模型、API base 和非生产 Key；
2. 明确允许发送该 manifest SHA 对应的已脱敏生产派生数据；
3. 使用生产派生数据专用确认口令；
4. 原始模型输出继续保存在仓库外 0700/0600 私有路径；
5. Git 只提交聚合指标、hash、计数和不含正文的失败分类。

生产 M22 shadow、历史回放、候选治理和容器更新均不属于本工作流授权。
