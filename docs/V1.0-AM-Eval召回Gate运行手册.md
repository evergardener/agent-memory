# Agent Memory for Hermes — AM-Eval v1 召回 Gate 运行手册

## 1. 用途与边界

`agent-memory-run-recall-benchmark` 将冻结 recall suite 通过真实 loopback HTTP API 执行，并生成不含
查询或记忆正文的可复算 query ledger。它验证：

- G02：6 次错误 namespace 请求没有返回任何记忆，且 API 全部以 403 拒绝；
- M05：10 个正样本的 Top-1 准确率；
- M06：同 10 个正样本的 Recall@5；
- M08：100 个负样本的误命中率；
- M21：110 个正常召回请求的 loopback HTTP p95 延迟。

这是公开合成回归 Gate，不是私有盲测。它不调用模型、不接触生产数据，也不能替代基于精确 OCI
digest 的正式 image-backed run。

运行必须满足：

- PostgreSQL 和 API 都只绑定 `127.0.0.1`、`localhost` 或 `::1`；
- 数据库名以 `am_eval_` 开头，并且除 API 启动时创建的目标 namespace/user subject 外没有记忆数据；
- namespace 以 `hermes:automated-tests:` 开头，API 只允许该 namespace；
- 输出位于源码仓库外 0700 私有目录，目标文件预先不存在；
- 结果仅保存 case ID、稳定 memory ID、前五名排序、命中布尔值、HTTP 状态和耗时；
- 每次运行使用新数据库，结束后停止 API 并删除数据库。

## 2. 冻结数据集

- manifest：`benchmarks/am-eval-v1/datasets/deterministic-gold-v1/manifest.json`
- manifest SHA-256：`6b06f88949f0acd135368ce8d8b4564e66f922eb54b083699d4ebb60c495f2cf`
- recall 文件 SHA-256：`a6095df16e56cba9100c46f6c829f84ff7613d55b338ad02c31fe56b18fa850d`
- 正样本：10 个自然改写；
- 负样本：25 UUID、25 hash、50 个无关文本；
- split：85 development、25 validation；
- namespace 探测：固定使用前 6 个正样本向错误 namespace 发起请求。

加载器会核验完整 manifest SHA、recall 文件 SHA、精确 case ID 集合、正负样本数、split、输入/期望
schema。任一项变化都在数据库或 API 调用前失败。

## 3. 隔离运行

先创建全新的 `am_eval_recall_<run-id>` 数据库并执行迁移。首次 Python/uv 命令前配置仓库外私有
bytecode cache：

```bash
export PYTHONDONTWRITEBYTECODE=1
export PYTHONPYCACHEPREFIX='/absolute/private/path/recall-pycache-<run-id>'
mkdir -m 700 "$PYTHONPYCACHEPREFIX"

export AGENT_MEMORY_DATABASE_URL='postgresql://agent_memory:<isolated-password>@127.0.0.1:55438/am_eval_recall_<run-id>'
export AGENT_MEMORY_NAMESPACE='hermes:automated-tests:am-eval-recall-<run-id>'
export AGENT_MEMORY_SERVICE_TOKEN='<random-test-token-at-least-16-chars>'
export AGENT_MEMORY_UI_SESSION_SECRET='<random-test-secret-at-least-32-chars>'

uv run alembic upgrade head
uv run uvicorn agent_memory.api:app --host 127.0.0.1 --port <random-loopback-port>
```

API ready 后在另一个受控 shell 执行：

```bash
MANIFEST='benchmarks/am-eval-v1/datasets/deterministic-gold-v1/manifest.json'
MANIFEST_SHA="$(shasum -a 256 "$MANIFEST" | awk '{print $1}')"

uv run agent-memory-run-recall-benchmark \
  "$MANIFEST" \
  --namespace "$AGENT_MEMORY_NAMESPACE" \
  --api-base 'http://127.0.0.1:<random-loopback-port>' \
  --output '/absolute/private/path/recall-result.json' \
  --confirm-sha256 "$MANIFEST_SHA"
```

密码和 token 只能来自本机受限 secret 或进程环境，不得写入仓库、报告或命令模板的真实值。API 启动
和 runner 必须共享同一个隔离数据库与 namespace。

## 4. 通过条件

| 项目 | 通过条件 |
| --- | ---: |
| 正样本 Top-1 | 至少 9/10 |
| 正样本 Recall@5 | 至少 9/10 |
| 负样本误命中 | 至多 1/100 |
| 越权召回条目 | 0/6 |
| 错误 namespace 拒绝 | 6/6 HTTP 403 |
| loopback HTTP p95 | 不高于 1000 ms |

runner 会完成所有正常查询与 namespace 探测，再从 ledger 计算聚合值。任何正常请求非 200、越权请求非
403、无效 UUID、非有限耗时或冻结覆盖不完整均失败关闭。输出为 0600；`FAIL` 结果写出后退出非零。

## 5. 来源证明

只有在已验证镜像内按精确 OCI digest 运行得到的 recall result，才能组装正式来源证明：

```bash
RESULT='/absolute/private/path/recall-result.json'
RESULT_SHA="$(shasum -a 256 "$RESULT" | awk '{print $1}')"

uv run agent-memory-assemble-eval-attestation recall \
  "$RESULT" \
  --confirm-source-sha256 "$RESULT_SHA" \
  --track deterministic-recall \
  --image-reference 'ghcr.io/evergardener/agent-memory-api@sha256:<64-hex>' \
  --image-platform linux/arm64 \
  --output '/absolute/private/path/recall-attestation.json'
```

组装器内嵌原始结果字节与 SHA，并从每条 ledger 重新计算 G02、M05、M06、M08、M21。它还会核对
case ID、排序布尔值、汇总计数、inclusive p95、dataset、source/environment 和 OCI 平台；不能由操作员
重新填写指标。

## 6. 清理与审核

1. 停止本轮 loopback API；
2. 删除 `am_eval_recall_<run-id>` 数据库并确认同名前缀残留为 0；
3. 确认结果文件 0600，且不含查询、事实正文、token 或数据库密码；
4. 保存 manifest SHA、结果 SHA、revision、source/environment SHA、聚合计数和 p95；
5. 运行 Ruff、全量非集成测试、隔离集成 Gate、uv lock 与 diff 检查；
6. 正式结果只能由 exact-digest 镜像重跑，本地 clean-checkout 数值只标记为诊断结果。
