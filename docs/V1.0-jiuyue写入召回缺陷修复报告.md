# Agent Memory V1.0 `jiuyue` 写入与召回缺陷修复报告

> 日期：2026-07-25。范围：真实生产只读调查、源码修复和隔离验证。本文不授权更新
> `agent-memory-production`、修改 Hermes profile 或治理生产数据。

## 1. 结论

`jiuyue` 的 ingest、worker 和 retrieval projection 在线，用户回合已经落库；“查询没有
数据”不是整体写入中断。真实复测暴露的是三项相互叠加的质量缺陷：

1. Hermes 传入完整会话历史，而 Provider 每回合重新遍历全部工具消息；
2. “不要使用某句式”被写为 candidate fact，又被召回出口的通用“不要”前缀过滤；
3. “那么记忆写入是否正常”等无问号中文问句没有被 query-only 规则识别。

生产只读快照中 `jiuyue` 已有 4 sessions / 18 turns / 1,449 events，最近多轮各写入
约 135–137 events；worker 无 failed job。直接 API 对照中，“记忆写入是否正常”
命中误生成的问句事实，而用户句式偏好的原文查询返回 0。以上证据确认“写入成功但采集
过量，偏好召回被过滤”。

## 2. 源码修复

### 2.1 当前回合边界

Provider 从完整 `messages` 末尾反向定位最后一个 `role=user`，只遍历其后的工具调用和
结果。用户和助手正文继续使用 `sync_turn` 的独立参数提交。没有 user 边界时仅把输入
视为调用者已经裁剪的 current-turn delta。重复提交同一个 session/turn 继续使用稳定
idempotency key。

### 2.2 中文分类与召回一致性

- 移除对普通“不要、禁止、允许、必须、如果”前缀的无条件召回封锁；
- 保留定时任务、目标字段、编号步骤等明确脚手架过滤；
- “不要/禁止/避免/允许/必须 + 使用、保存、删除、同步等”识别为长期偏好或约束；
- 增加“是否、能否、可否、有没有、是不是、在哪里、多少、怎么、如何、吗、呢”等
  中文问句形态，问句只留 evidence；
- `NO_MEMORY_PATTERN` 仍优先，“不要保存/不要记住”不会变成可召回事实。

### 2.3 浏览与空结果诊断

新增 `GET /api/v1/memories` 和 `agent_memory_browse`。浏览默认限定当前 profile，可按
profile、fact type、state、updated-after 和 limit 筛选，返回脱敏事实、状态、更新时间
和 evidence IDs。显式召回为空时返回 `status=no_match` 和浏览提示，不再让空
`context` 被解释为写入失败。

### 2.4 既有重复数据边界

本次源码提交不删除或改写生产只读 evidence。召回与浏览对同 profile 完全同文事实合并
展示并合并 evidence IDs，避免重复内容放大回答；质量报告新增
`repeated_tool_event_groups` 和 `repeated_tool_event_copies`，用于生产更新前后审计。
任何隔离、重建或物理清理仍须先生成最新可恢复备份、固定影响清单并单独批准。

## 3. 回归与完成标准

本提交必须证明：

- 累计两轮 `messages` 只采集最新回合的工具事件；
- 内部 `agent_memory_*` 工具仍不回灌；
- 中文偏好被分类为 `long_term/active` 且可召回；
- 无标点中文问句不创建 fact；
- API 浏览支持 namespace/profile/state 过滤并拒绝错误 namespace；
- Provider 浏览默认使用当前 profile，空召回给出 `no_match`；
- 同文事实合并展示并保留全部 evidence IDs；
- Ruff、完整 pytest、真实 Hermes Provider、API/数据库、worker 故障、前端构建、
  备份恢复、Vault 解密和 handoff Gate 全部通过。

验证结果在完整 Gate 完成后回填。生产仍运行旧 revision，在备份、部署批准和真实
写入/浏览/召回复测完成前保持 `canary_active`，不得晋级。
