# Agent Memory for Hermes — AM-Eval v1 情节与程序 Gate 运行手册

## 1. 用途与边界

`agent-memory-run-episode-procedure-benchmark` 使用 21 条冻结公开合成 case，验证时间解析、情节抽取、
实体角色、当前事实与偏好替代、程序适用性以及 procedure → episode → fact → evidence 来源链。它只测量：

- G04：已选择情节中把 Hermes profile 名误当真实人物的数量；
- G08：程序 case 中发生未授权自动应用的数量；
- M04：实体与角色精确匹配率；
- M09：日期范围与纪念日时间规则解析准确率；
- M10：当前事实与偏好的替代链完整率；
- M11：情节结构精确率；
- M12：程序适用状态精确率；
- M13：危险/不适用程序被自动应用的比例；
- M14：程序到情节、事实和精确 evidence event 的来源链完整率。

这是公开合成、非盲、无模型的确定性 Gate，不替代私有 blind 质量评测或生产分布测量。输入含合成生活、
纪念日、偏好和技术排障文本；结果只保存 case ID、布尔值、状态和聚合计数，不保存输入正文。

运行必须满足：

- PostgreSQL 只使用 loopback 地址，数据库名以 `am_eval_` 开头；
- 运行前数据库没有任何 namespace；
- namespace 以 `hermes:automated-tests:` 开头；
- 输出位于源码仓库外 0700 私有目录，目标文件不存在；
- 不启动或连接生产 API/worker，不调用模型，不读取外部 key；
- 每次运行创建新数据库，结束后删除并确认无残留。

- manifest：`benchmarks/am-eval-v1/datasets/episode-procedure-gold-v1/manifest.json`
- manifest SHA-256：`8f212b3c435a7109a03ada28cf0a015f0f07339354e79a92dad4f4e3ed9b6fb7`
- case 文件 SHA-256：`6e85413ef239ab46cf5caf9fb8057f0935b5976f3cb3380c2e500df27f8c0b6f`
- case：21 条，11 development、10 validation；
- suite：6 date range、4 temporal rule、4 episode、4 procedure、3 database scenario；
- database scenario：current supersession、preference supersession、procedure lineage。

加载器核验完整 manifest/case SHA、精确 case ID、split、suite 数量、程序预期状态和数据库 invariant
集合。修改任一冻结字段、case 数量或 suite 归属都会失败关闭。

## 3. 隔离运行

首次 Python/uv 命令前配置仓库外私有 bytecode cache：

```bash
export PYTHONDONTWRITEBYTECODE=1
export PYTHONPYCACHEPREFIX='/absolute/private/path/episode-procedure-pycache-<run-id>'
mkdir -m 700 "$PYTHONPYCACHEPREFIX"

export AGENT_MEMORY_DATABASE_URL='postgresql://agent_memory:<isolated-password>@127.0.0.1:55438/am_eval_episode_<run-id>'
export AGENT_MEMORY_SERVICE_TOKEN='<random-test-token-at-least-16-chars>'
export AGENT_MEMORY_UI_SESSION_SECRET='<random-test-secret-at-least-32-chars>'

uv run alembic upgrade head

MANIFEST='benchmarks/am-eval-v1/datasets/episode-procedure-gold-v1/manifest.json'
MANIFEST_SHA="$(shasum -a 256 "$MANIFEST" | awk '{print $1}')"

uv run agent-memory-run-episode-procedure-benchmark \
  "$MANIFEST" \
  --namespace 'hermes:automated-tests:am-eval-episode-<run-id>' \
  --output '/absolute/private/path/episode-procedure-result.json' \
  --confirm-sha256 "$MANIFEST_SHA"
```

数据库密码和测试 token 只能从本机受限 secret 或进程环境读取，不能写入仓库或报告。

## 4. 原始 ledger 与通过条件

runner 生成四类 metadata-only ledger：temporal、episode、procedure 和 database。通过必须同时满足：

| 项目 | 通过条件 |
| --- | ---: |
| temporal | 10/10 |
| episode structure | 4/4 |
| profile/subject confusion | 0/2 selected episode |
| entity + role | 6/6，unexpected=0 |
| procedure status | 4/4 |
| unauthorized auto apply | 0/4 |
| dangerous auto apply | 0/3 |
| database invariant | 3/3 |
| supersession | 2/2 |
| procedure lineage | 1/1 |

数据库场景必须由真实 repository/unified-memory 路径创建记录并查询最终状态。M14 还必须核对 procedure
关联的 active episode、support fact、fact evidence link 和唯一 evidence event ID。任一 ledger 与汇总不一致、
旧/新记录状态错误、自动应用非 false、来源链断裂或数据库非空，runner 都失败关闭。结果写为 0600；
`FAIL` 退出非零。

## 5. 来源证明

只有在已验证镜像内按精确 OCI digest 运行的结果可组装正式来源证明：

```bash
RESULT='/absolute/private/path/episode-procedure-result.json'
RESULT_SHA="$(shasum -a 256 "$RESULT" | awk '{print $1}')"

uv run agent-memory-assemble-eval-attestation episode-procedure \
  "$RESULT" \
  --confirm-source-sha256 "$RESULT_SHA" \
  --track deterministic-episode-procedure \
  --image-reference 'ghcr.io/evergardener/agent-memory-api@sha256:<64-hex>' \
  --image-platform linux/arm64 \
  --output '/absolute/private/path/episode-procedure-attestation.json'
```

组装器从四类原始 ledger 复算 G04、G08、M04、M09–M14，并核验冻结 dataset、source/environment、
原结果 SHA、OCI digest 与平台。操作员不能重新填写测量值。

## 6. 清理与审核

1. 删除 `am_eval_episode_<run-id>` 数据库并确认同名前缀残留为 0；
2. 确认结果文件为 0600，且不含冻结输入正文、真实 secret 或数据库密码；
3. 保存 manifest/result SHA、revision、source/environment SHA 和聚合计数；
4. 运行 Ruff、全量非集成测试、隔离数据库集成 Gate、uv lock 与 diff 检查；
5. 本地 clean-checkout 结果只用于诊断；正式 run 必须在 exact-digest 镜像内重跑。
