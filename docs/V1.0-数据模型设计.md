# Agent Memory for Hermes — V1.0 数据模型设计

> 2026-07-26 实施修订：Subject 身份层、`display_name_origin` 和关系星系已经落地。
> 本文新增的多实体情节、时间规则、偏好演化、知识制品和程序性记忆字段是下一阶段目标模型，
> 尚未迁移；`1.0.0-rc.8` 的现有 episode/arc 必须按兼容迁移处理，不得被文档误标为已实现。

## 1. 数据建模原则

1. **证据优先**：原始事件不可由整理流程覆盖；所有派生记忆可追溯到证据或人工操作。
2. **派生可重建**：事实以外的叙事、索引、向量、关系聚合、星图布局均可失效并重建。
3. **敏感隔离**：Vault 密文与普通记忆使用不同 schema；普通表只允许脱敏引用。
4. **版本而非覆写**：更正产生替代链与重建请求，不抹去原有历史；永久清除是唯一删除语义。
5. **一切可审计**：自动决策、用户治理、召回与 Vault 访问均记录操作主体、时间、目标和依据。
6. **身份与投影分离**：主体、canonical entity、事实分类和星图布局是不同维度；恒星/行星/星系均不得复制或改写底层事实。
7. **关系语义分层**：依赖类型、传输路径与社区成员分别建模；路径变化不覆盖业务关系，社区重建不改写路径事实。
8. **来源与参与者分离**：`source_profile` 表达记录来源；事件主体、执行者和参与者使用显式角色关联，不由来源字段推断。
9. **事件与时间一等建模**：episode 具有时间范围、精度、时区和步骤；普通日期不创建 entity，重复日期使用独立时间规则。
10. **程序有适用条件**：程序性记忆必须版本化并绑定支撑情节、当前适用条件、停止条件和安全门控。

所有业务主键使用 UUID；时间为 `timestamptz`；正文采用 UTF-8 `text`；枚举先以受约束的 `text` 值实现，避免早期数据库迁移僵化。所有用户数据表均含 `namespace_id`（Vault 密文表可经关联取得）与 `created_at`/`updated_at`。

## 2. Schema 与核心表

### 2.1 `core`

| 表 | 关键字段 | 语义 |
| --- | --- | --- |
| `namespaces` | `id`, `stable_key`, `status` | 单用户的稳定共享命名空间；`stable_key` 唯一 |
| `subjects` | `id`, `namespace_id`, `kind`, `entity_id`, `stable_key`, `display_name`, `display_name_origin`, `color`, `status` | 用户/profile 人格主体；引用 canonical entity；星图投影为恒星；名称来源为 `default|source|manual` |
| `subject_sources` | `source_id`, `subject_id`, `mapping_origin` | 每个实际来源只映射一个主体；同 profile 默认复用稳定 Subject，人工映射优先且可审计 |
| `sources` | `id`, `namespace_id`, `subject_id`, `source_profile`, `source_instance` | Hermes profile/实例来源，不是存储隔离边界；不得自动成为星体 |
| `sessions` | `id`, `namespace_id`, `source_id`, `external_session_id`, `started_at`, `ended_at` | 外部会话边界；`namespace + source + external_session_id` 唯一 |
| `turns` | `id`, `session_id`, `external_turn_id`, `sequence_no`, `status` | 回合归属与排序，供幂等事件关联 |

### 2.2 `evidence`

| 表 | 关键字段 | 不变量 |
| --- | --- | --- |
| `events` | `id`, `namespace_id`, `turn_id`, `event_type`, `redacted_payload`, `payload_hash`, `occurred_at`, `retention_class`, `ingest_key` | 仅追加；`ingest_key` 全局唯一；正文为脱敏副本 |
| `event_links` | `event_id`, `related_event_id`, `relation_type` | 表达消息、工具调用、结果、观察之间的关联 |
| `redaction_findings` | `event_id`, `kind`, `span_hash`, `action`, `rule_version` | 记录检测结果，不保存原始敏感值 |

`event_type` 至少包括 `user_message`、`assistant_message`、`tool_call`、`tool_result`、`environment_observation`、`session_boundary`。工具参数/推理摘要只能以脱敏、受策略控制的关联证据保存；不得默认保存模型私有推理链。

| --- | --- | --- |
| `facts` | `id`, `namespace_id`, `fact_type`, `statement`, `confidence`, `valid_from`, `valid_to`, `memory_state`, `supersedes_fact_id`, `version` | 原子、可证实的陈述；长期/阶段/当前以 `fact_type` 区分 |
| `fact_evidence` | `fact_id`, `event_id`, `support_kind`, `weight` | 一个事实必须至少有一条 `support` 或人工更正依据 |
| `entities` | `id`, `namespace_id`, `entity_type`, `canonical_name`, `normalized_name`, `merge_state`, `canonical_entity_id` | 唯一规范实体源；普通实体投影为行星，关联 Subject 的实体投影为恒星且同画面不重复；内部 ID、事实片段、状态键和值不成为天体 |
| `entity_aliases` | `id`, `namespace_id`, `entity_id`, `alias`, `normalized_alias`, `origin`, `confidence`, `review_state` | 产品旧名/UI 名/来源别名先映射到规范实体；映射可撤销且同 namespace 归一化别名唯一 |
| `fact_entities` | `fact_id`, `entity_id` | 事实与实体的证据关系 |

| `relation_facts` | `relation_id`, `fact_id`, `support_kind`, `weight` | 关系与事实依据；社区权重可回溯到事实和 evidence |
| `episodes` | `id`, `namespace_id`, `episode_type`, `anchor_entity_id`, `title`, `summary`, `started_at`, `ended_at`, `time_precision`, `timezone`, `importance`, `review_state`, `state`, `origin`, `extractor_version`, `confidence`, `version` | 多实体时间经历；锚点可空；标题、日期和摘要不成为实体；当前 rc.8 只有基础字段 |
| `episode_facts` | `episode_id`, `fact_id` | episode 的全部支撑事实；可继续回溯到 evidence |
| `episode_entities` | `episode_id`, `entity_id`, `subject_id`, `role`, `fact_id`, `confidence`, `origin` | 主体、参与者、地点、对象、受影响对象和制品；`entity_id`/`subject_id` 按角色二选一；必须有事实或人工依据 |
| `episode_steps` | `id`, `episode_id`, `sequence_no`, `parent_step_id`, `branch_key`, `step_kind`, `summary`, `occurred_at`, `status`, `fact_id`, `evidence_event_id`, `confidence` | 经历、动作、观察、假设、结果、原因、解决、验证或里程碑；顺序不自动表达因果 |
| `temporal_rules` | `id`, `namespace_id`, `owner_subject_id`, `owner_entity_id`, `rule_type`, `label`, `month`, `day`, `year`, `timezone`, `recurrence`, `sensitivity`, `reminder_policy`, `fact_id`, `review_state`, `state`, `version` | 生日、纪念日等重复时间事实；记忆日期与允许提醒分离 |
| `preference_assertions` | `id`, `namespace_id`, `subject_id`, `topic_entity_id`, `aspect`, `polarity`, `strength`, `explicitness`, `valid_from`, `valid_to`, `fact_id`, `state`, `supersedes_id`, `version` | 长期偏好的可查询投影；明确表达优先，行为推断只可为候选 |
| `artifacts` | `id`, `namespace_id`, `artifact_type`, `title`, `reference_uri`, `content_hash`, `summary_redacted`, `sensitivity`, `state`, `version` | 变更报告、知识库记录、照片说明等制品引用；默认不复制外部文件全文 |
| `episode_artifacts` | `episode_id`, `artifact_id`, `role`, `fact_id` | 情节与报告/制品的可追溯关联 |
| `procedures` | `id`, `namespace_id`, `title`, `goal`, `scope`, `preconditions`, `environment_fingerprint`, `risk_level`, `state`, `review_state`, `valid_from`, `valid_to`, `supersedes_id`, `version` | 从已验证情节提炼的程序性记忆；不是执行授权 |
| `procedure_steps` | `id`, `procedure_id`, `sequence_no`, `parent_step_id`, `branch_key`, `instruction`, `expected_observation`, `success_condition`, `failure_condition`, `stop_condition`, `required_permission`, `risk_level` | 有序步骤、分支、观察和安全门控；不得保存 Vault 明文 |
| `procedure_support` | `procedure_id`, `episode_id`, `fact_id`, `artifact_id`, `support_kind`, `weight` | 程序的成功、反例和上下文支撑；至少一条已验证 episode 支撑才能 active |
| `arcs` | `id`, `namespace_id`, `anchor_entity_id`, `title`, `summary`, `state`, `version` | 多情节/长期事实形成的保守脉络；锚点可空 |
| `arc_facts` | `arc_id`, `fact_id` | arc 的全部支撑事实；V1 不生成无证据叙事 |
| `arc_episodes` | `arc_id`, `episode_id`, `sequence_no` | 长期星流的可追溯情节顺序 |

### 2.4 `state`

| 表 | 关键字段 | 语义 |
| --- | --- | --- |
| `current_items` | `id`, `namespace_id`, `statement`, `status`, `expires_at`, `source_fact_id` | 天气、进行中事项等；到期后不主动召回 |
| `continuities` | `id`, `namespace_id`, `topic_key`, `summary`, `last_active_at`, `expires_at` | 跨会话短期连续性 |
| `interaction_snapshots` | `id`, `namespace_id`, `subject_id`, `axes`, `calculated_at`, `algorithm_version` | profile 人格 Subject 的 jiwen 理念状态快照；不形成独立事实空间 |
| `settings` | `namespace_id`, `enabled`, `drift_hours`, `axes_initial`, `axis_labels`, `axis_ranges`, `axis_enabled`, `thresholds`, `subject_overrides` | namespace 默认配置与人格覆盖控制面；修改与重置进入 audit |

### 2.5 `retrieval`

`documents` 是事实、实体概览、episode、arc、时间规则、偏好、程序和状态的可丢弃检索投影。字段包括 `id`、`namespace_id`、`source_kind`、`source_id`、`text_redacted`、`tsv`、`embedding`、`embedding_model_version`、`lifecycle_state`、`indexed_at`。它不保存 Vault 明文，也不替代来源表。

### 2.6 `projection`

`projection` 保存可重建星图结果和不可被重建覆盖的人工布局治理，两类数据必须用 `origin`/`manual_state` 明确区分。

| 表 | 关键字段 | 语义 |
| --- | --- | --- |
| `galaxies` | `id`, `namespace_id`, `stable_key`, `family`, `display_name`, `name_origin`, `origin`, `algorithm_version`, `input_snapshot_hash`, `lifecycle_state`, `visibility`, `manual_locked`, `version` | 关系社区；不对应 fact_type；自动结果可重建，人工名称和锁定状态可保留 |
| `galaxy_memberships` | `galaxy_id`, `namespace_id`, `entity_id`, `weight`, `role`, `membership_kind`, `governance_state`, `algorithm_version` | 行星多对多软归属；`membership_kind=primary` 仅控制布局，`fixed/excluded` 优先于自动结果 |
| `galaxy_membership_evidence` | `id`, `galaxy_id`, `entity_id`, `relation_id`, `fact_id`, `event_id`, `origin` | 自动归属解释；每条记录可回到 relation/fact/evidence，不保存不可复核的模型分数 |
| `layout_preferences` | `id`, `namespace_id`, `scope_kind`, `scope_id`, `target_kind`, `target_id`, `position`, `zoom`, `motion_enabled`, `pinned`, `version` | 主宇宙/子星系相机、星系和行星位置及动态偏好；不参与事实召回 |

`galaxies` 不允许由单个行星自动产生。自动社区的主体输入是当前有效的行星—行星关系；Subject—entity 关系只用于视角、排序和解释，不能单独形成星系。

### 2.7 `vault`、`ops` 与 `audit`

| schema | 表 | 关键字段 |
| --- | --- | --- |
| `vault` | `entries` | `id`, `namespace_id`, `kind`, `display_label`, `redacted_hint`, `ciphertext`, `wrapped_dek`, `key_version`, `status` |
| `vault` | `grants` | `id`, `entry_id`, `grantee`, `operation`, `target_constraint`, `expires_at`, `revoked_at` |
| `ops` | `jobs` | `id`, `kind`, `idempotency_key`, `input_version`, `status`, `run_after`, `attempt_count`, `payload_ref` |
| `ops` | `job_attempts` | `job_id`, `started_at`, `ended_at`, `result`, `error_code`, `correlation_id` |
| `audit` | `events` | `id`, `actor_type`, `actor_id`, `action`, `target_type`, `target_id`, `reason`, `correlation_id`, `metadata_redacted` |

Vault 条目在星图中的关联由普通 `memory` 表存储 `vault_entry_id` 的受限引用或专门的 `vault_references` 表表达，且只提供 `display_label`/`redacted_hint`。

## 3. 生命周期状态机

### 3.1 证据

`accepted → retained → purge_requested → purged`。`accepted` 和 `retained` 不可编辑；脱敏规则升级时可增加新投影，但不覆盖旧内容。`purged` 仅保留最小化、无正文的审计事实。

### 3.2 事实与关联

`candidate → active → dormant → forgotten` 是默认生命周期；`isolated` 表示用户删除关联后不参与召回；`superseded` 指向更正版本；`purge_requested → purged` 由永久清除工作流执行。`forgotten` 不主动召回，但命中明确主题时可作为低权重历史候选。任何自动生成记录不得直接进入 `active`，除非证据规则/置信度阈值满足。

### 3.3 派生叙事与投影

V1 采用事务内“删除旧自动投影并从当前有效事实重建”的保守策略。上游事实被更正、遗忘、孤立或清除时均入队 `rebuild_derived`；不足支撑的 episode/arc 和自动星系自动撤销。人工 Subject/source 映射、星系名称/成员固定、排除和布局偏好不得随自动重建删除。后续若需要长时间模型整理，再引入显式 `stale/rebuilding` 状态。

下一阶段的 episode、时间规则、偏好投影和程序也遵守相同原则。程序失去全部有效验证支撑、
适用环境过期或被上游更正影响时必须转为 `candidate|dormant|superseded`，不能继续作为默认建议。
人工确认记录不随自动重建删除，但其目标失效时必须在 UI 中显示为需要复核。

## 4. 完整性与约束

- `facts`、`entity_relations`、`episodes`、`arcs` 与其支撑对象必须位于同一 namespace。
- `episode_entities` 的 Subject/entity 必须位于同一 namespace；记录来源不得自动填充为参与者。
- `episode_steps.sequence_no` 在同一 episode 内稳定且唯一；步骤顺序不自动生成 `caused_by`。
- `started_at <= ended_at`；模糊时间必须记录 `time_precision`，不能伪造缺失时刻。
- 普通日期、时间戳、步骤、事实句子和摘要不得写入 `entities`。
- 重复时间规则必须区分日期事实和提醒策略；没有授权的提醒策略固定为关闭。
- `preference_assertions.explicitness=inferred` 的记录只能进入候选状态，不能自动成为 active 长期偏好。
- active 程序必须至少有一条已验证 episode 支撑，并包含停止条件、权限要求和适用范围。
- 程序步骤禁止保存密码、Token、私钥、Cookie 或其他 Vault 明文。
- artifact 默认只保存脱敏摘要、引用和内容哈希；外部文档正文是否导入须走独立证据策略。
- `subjects.entity_id` 必须指向同 namespace 的 canonical entity；一个来源在同一有效期内只能解析到一个有效 Subject。
- Subject 对应实体在同一星图投影中只能出现一次：作为恒星时不得再生成行星节点。
- `display_name` 只是可见标签，不得参与 Subject 唯一性、source 映射或记忆归属；`display_name_origin=manual` 的名称不得被后台 profile 同步改写。
- 旧数据回填时，有 `subject.update` 治理审计的名称标记为 `manual`；其他内置 `User`/`Hermes · *` 默认名按 `default|source` 迁移，回填不改变 `id`、`stable_key`、`entity_id` 或 source 映射。
- 自动事实的 `confidence`、抽取版本、模型配置版本和至少一个证据关联为必填；人工事实须有审计原因。
- `entity_aliases` 必须在建边前解析；同一规范实体的两个别名不得产生关系或自环。
- V1 的 `entity_relations` 两个实体不可相同；业务关系与 `transport` 变更分别版本化。
- `galaxy_memberships` 允许一个实体属于多个星系；实体表不得保存唯一 `galaxy_id` 作为事实属性。
- 自动星系至少包含三个 canonical entity 和两条独立、可追溯的行星关系链；具体可调阈值不能破坏该防单体边界。
- `current_items.expires_at` 必填且受最大 TTL 策略约束。
- 普通表与检索表禁止含 `vault.entries.ciphertext` 的可解密副本、敏感原文或根密钥。
- 用户操作“删除”仅改为 `isolated` 并断开关系；“忘记”降低召回状态；“更正”创建新版本；“永久清除”才触发物理删除/加密销毁。

## 5. 索引与分区基线

- 所有高频查询以 `(namespace_id, status/state, updated_at)` 为基础复合索引。
- `events.ingest_key`、`jobs.idempotency_key` 为唯一索引。
- `documents.tsv` 建 GIN FTS 索引；短名称和命令字段采用 `pg_trgm` 索引。
- 向量索引以真实数据基准后选用精确扫描或 HNSW；任何向量检索均先做 namespace/scope/lifecycle 过滤。
- 审计和证据在规模增长后按月分区，但 V1 初始迁移不应为尚未发生的规模提前复杂化。
- 星系查询以 `galaxies(namespace_id, state)`、`galaxy_memberships(galaxy_id, weight)` 和 `galaxy_memberships(entity_id)` 为基础索引；人工固定/排除状态必须优先于自动权重排序。
- 情节查询至少覆盖 `(namespace_id, started_at, ended_at, episode_type, state)`、参与 Subject/entity 和地点。
- 时间规则以 `(namespace_id, month, day, state)` 支持周年查询，但提醒调度必须额外检查授权策略。
- 程序查询以目标、适用实体、环境指纹、状态和版本为过滤条件；任何语义检索之前先过滤失效/未确认程序。
