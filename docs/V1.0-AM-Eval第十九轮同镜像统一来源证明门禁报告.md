## 2. 本轮补齐的结构缺口

旧 `am-eval-run-v2` 只能声明一个 dataset manifest，因此不能同时合法绑定五个冻结数据集。直接拼接会
使四个 artifact 触发 dataset binding mismatch。本轮新增：

1. `am-eval-run-v3`：显式声明按 ID 排序、ID/SHA 唯一的 `datasets`；
2. `am-eval-run-attestation-v2`：绑定完整 manifest SHA 列表；
3. artifact 必须唯一匹配一个声明 dataset，且所有声明 dataset 都必须被使用；
4. `agent-memory-assemble-deterministic-run`：只接受五种固定 sourced artifact，自动复算覆盖并生成
   正式部分 run；
5. 保持单数据集 v2/v1 的兼容性回归。

## 3. 镜像执行中发现并修复的问题

### 3.1 默认 pycache 权限错误

原 Dockerfile 在创建运行用户前设置 `PYTHONPYCACHEPREFIX`。构建阶段生成了 root:root 0755 目录，导致
正式 runner 在任何业务写入前 fail-closed。修复后目录由镜像显式创建为 10001:10001、0700、空目录，
镜像 verifier 不再用临时 ENV/tmpfs 掩盖默认配置。

### 3.2 OCI overlay 硬链接误判

运行环境指纹原先复用私有 dataset 的“单链接文件”规则；OCI overlay 中安装包 METADATA 可能有多个
只读硬链接，导致环境指纹 fail-closed。修复后：

- dataset、plan、输出与 attestation 仍必须单链接；
- 依赖指纹仅允许非当前用户所有、组/其他用户不可写的只读硬链接；
- 仍通过 O_NOFOLLOW 文件描述符读取并在读取前后核对 inode/size/mtime/ctime。

## 6. 结果解释与下一步

本轮证明了所有确定性 Gate 可以在一个不可变运行身份中共同成立，消除了“各轮在不同提交分别通过”
的证据割裂；但不能把 73% 覆盖的满分解释为完整产品评分。

4. 如需远端 CI 证据，创建 PR 触发 image-contract，但不自动 merge 或部署。
