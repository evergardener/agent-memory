## 1. 为什么重做可靠性来源路径

旧 G07/G10/M18/M19/M20 只引用 release-check 文本，例如“worker 重启后完成”或“28 类计数一致”。
这些描述没有绑定原始 job、dump、恢复库或 Vault 密文，也无法防止分母和结果重填。本轮改为两阶段
receipt：

```text
frozen metadata-only reliability cases
  -> real worker job state + evidence hash + idempotency ledgers
  -> source 47-table snapshot + synthetic Vault ciphertext
  -> private prepare receipt
  -> real custom-format pg_dump / distinct database pg_restore
  -> source versus restore verification
  -> metadata-only final result
  -> reliability sourced attestation adapter
```

输入和输出均不含生产数据；Vault 使用每次运行新生成的测试 root key 和固定合成 probe。key 在 Gate
结束时删除。

## 3. 实现与 fail-closed 回归

1. 新增 5 条冻结 metadata-only reliability gold，固定 case/suite/split、attempt 数和 invariant 集合。
2. prepare 仅接受 loopback `am_eval_` 空库、自动化 namespace、仓库外私有 key/output；worker outage
   必须先观察到 2 个 pending job，再处理到 done 且 evidence hash 不变。
3. expired lease 必须回收精确 job，`attempt_count` 从 1 变 2，不能以其他成功 job 代替。
4. 顺序与并发 replay 都由真实 repository 数据库唯一约束判定 winner 和最终基数。
5. 业务 table set 从数据库冻结为 47 个 base table；新增、缺失或改名都会在 snapshot 阶段失败。
6. verify 绑定 prepare SHA 和 custom dump SHA，比对源/恢复库 47 表计数、迁移 revision、evidence 摘要、
   Vault 密文摘要，并在两个库实际解密同一条目。
7. reliability attestation v1 内嵌原结果字节与 SHA，从三个 ledger 复算五项测量，并绑定 source、
   environment、dataset、OCI digest 与平台。

攻击测试覆盖：dataset/case 重写、worker/lease ledger 布尔值、idempotency winner/duplicate 数、恢复布尔
值、聚合计数、prepare/dump SHA、私有路径 symlink 和 formal artifact 覆盖。任一 ledger 与汇总同步不
一致都会失败关闭。
