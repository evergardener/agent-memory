# Agent Memory V1.0 模型辅助记忆准入与治理设计

## 1. 背景与问题

2026-08-01 对生产环境的只读排查确认：生产模型开关关闭，待治理队列共有 54 项，全部为
candidate；其中多数来自确定性提取器，包含“继续”“允许”“再试一次”等无独立记忆价值的
对话片段。另有“现在过去了几个小时再试试呢”因“过去了”包含“去了”而被旅行正则误匹配，
生成“几个小时再试试呢”地点实体、旅行情节和无意义关系。

这说明问题不只是“没有启用大模型”：当前确定性默认准入、模型与规则双通路、candidate 星图
投影和人工治理入口之间缺少统一的产品契约。仅打开模型不会自动删除既有垃圾项，也不能保证
模型结果把同一确定性 candidate 正确晋级为 active。

本设计只定义源码与隔离验证方案。生产模型启用、已有 54 项重分类、容器更新和 namespace
变更均为独立授权面。

## 2. 目标与非目标

目标：

1. 保存可追溯证据，但不把所有对话变成事实或人工任务。
2. 让高置信明确内容多数自动纳入，人工只处理真实歧义。
3. 对日常生活和技术协作采用同一准入语义与证据标准。
4. 阻止 candidate 和临时实体污染默认召回与星图。
5. 模型关闭、超时或输出非法时安全降级，不丢证据、不制造治理洪峰。

非目标：

- 不自动删除原始 evidence。
- 不在本批次批量改写生产 candidate。
- 不允许模型推理链、常识补全或助手未验证说法成为事实。
- 不因历史程序可用而授权 Hermes 自动执行工具或读取 Vault。

## 3. 四态准入状态机

每个事件先完成脱敏和确定性预过滤，再由规则或模型给出结果：

```text
原始事件
  ├─ 禁止记忆/重复/无价值 ──> discard
  ├─ 问询/控制/衔接/暂不可判 ─> evidence_only
  └─ 有潜在记忆价值
       ├─ 明确且通过全部门禁 ─> accept ─> active
       └─ 冲突/角色歧义/高风险 ─> review ─> candidate
```

`discard` 表示不派生记忆；原始事件是否保留仍由证据保留策略决定。`evidence_only` 可供追溯和
显式回放，但不进入普通召回、星图或整理报告。`accept` 创建 active 派生记忆。`review` 是唯一
进入“待治理记忆”的结果。

## 4. 确定性预过滤

以下内容直接 evidence-only，不调用模型或创建 candidate：

- 问询与检索请求；
- “继续”“允许”“确认”“再试一次”“按计划进行”等无独立命题的短控制语句；
- assistant 未被用户或工具验证的陈述；
- 内部记忆工具回显、结构化大段输出、命令片段和纯标量；
- 明确要求“不保存/不要记住”的内容。

高精度规则仍可直接 accept：明确偏好指令、带有效期的当前状态、可信工具观测，以及经过负例
验证的明确事实模式。无法落入高精度规则的用户陈述默认 evidence-only，并在模型启用时交给
模型判断，而不是直接 candidate。

旅行识别要求“去/前往”具有动作边界和有效地点，禁止在“过去了”“失去了”等词内部匹配。

## 5. 模型结构化契约

模型每次返回最多八条原子事实：

```json
{
  "facts": [
    {
      "evidence_index": 0,
      "statement": "必须是单条 Evidence 中的连续原文",
      "fact_type": "long_term|stage|current|observed",
      "admission": "accept|review",
      "confidence": 0.0,
      "review_reason": "仅 review 时填写受限原因",
      "entities": [
        {"name": "statement 内连续原文", "type": "受限实体类型"}
      ]
    }
  ]
}
```

模型通过返回空 `facts` 表达 discard/evidence-only；审计记录预过滤结果、模型是否调用、输出数量、
拒绝原因和版本。`accept` 必须满足置信度不低于 0.80、精确证据 span、合法类型、可召回内容和
安全门禁。`review` 必须提供受限原因，例如 `conflict`、`identity_ambiguity`、
`role_ambiguity`、`sensitive_boundary` 或 `high_value_low_confidence`；缺少合法原因则拒绝。

## 6. 幂等、晋级与人工优先

- 同一 event + statement 使用稳定 ID；规则和模型不得创建两个事实。
- 模型 `accept` 可以把同一自动生成的 candidate 晋级为 active，但只能针对未被人工治理的记录。
- 模型不得覆盖用户确认、更正、忘记、脱离、清除或 replacement 链。
- 模型输出的事实、实体、span、版本和模型名写入审计；非法输出只记录拒绝统计。
- 自动准入和关系/情节提取必须可重复执行，重复回放的行数和状态保持稳定。

## 7. 情节、关系与星图投影

明确旅行、见面、纪念日、偏好和技术经历可形成结构化记忆，但来源 profile 不自动成为经历
参与者。日期是情节属性，步骤是时间线内容，二者不生成行星。

默认星图只显示：

- active 事实和 active 情节；
- 至少被一条 active 事实、active 情节或 active 关系支撑的实体；
- 只由 active 情节支撑的共同情节桥。

candidate 情节、candidate 关系及其临时实体只在治理视图中显示，不能进入默认星图、普通召回
或自动社区计算。情节确认后投影才原子化出现；忘记或脱离后同步消失。

## 8. 模型故障与回放

模型关闭、超时、限流或输出非法时：

1. 原始 evidence 正常保存；
2. 高精度确定性 active 结果正常保存；
3. 其余内容保持 evidence-only，不创建 candidate；
4. 失败任务有界重试并记录审计，不阻断 Hermes 对话；
5. 恢复后只通过显式回放命令重判指定时间、来源或 event 范围，先 dry-run 再 apply。

`AGENT_MEMORY_MODEL_AUTO_BACKFILL_ENABLED` 默认必须为 `false`。启用实时模型只处理启用后新
写入的 turn，不等价于授权历史回放；自动历史 backfill 需要独立的数据范围与费用授权。

## 9. 历史治理债务

现有 candidate 先执行只读 dry-run，输出 `discard/evidence_only/accept/review` 建议、原因、来源、
关联实体/情节影响和预计队列缩减。批量 apply 前必须有新鲜备份、恢复验证、确认哈希、回滚方案
和用户单独授权；默认不删除 evidence。

## 10. Gate 与质量指标

必须覆盖以下回放：

| 输入/场景 | 预期 |
| --- | --- |
| “继续”“允许”“再试一次” | evidence-only；0 事实、0 实体、0 情节、0 review |
| “现在过去了几个小时再试试呢” | 非旅行；0 地点、0 情节、0 review |
| “7月10日-7月11日去了成都旅游……” | active 旅行情节，时间/主体/人物/地点/体验角色正确 |
| 明确生日、偏好 | 进入对应结构，不由单次行为推断偏好 |
| n8n 与 Next Terminal 排障 | 保留问题、步骤、原因/假设、验证和报告证据边界 |
| 模型关闭/超时/非法 JSON | evidence 保留、0 candidate 洪峰、Hermes fail-soft |
| 同一 turn 重复处理 | 无重复事实、实体、情节或关系 |

质量报告至少包含：自动 accept 准确率、误收率、漏收率、review 比例、无效实体率、重复率、
证据 span 通过率和模型故障降级计数。模型可处理金标样本的 review 比例目标不高于 10%。

## 11. 实施顺序与生产边界

1. 文档与负例冻结；
2. 确定性预过滤和旅行误判修复；
3. 模型 admission/schema/幂等晋级；
4. candidate 星图隔离；
5. 单元、数据库、API、浏览器、故障恢复和历史回放 Gate；
6. 独立 Review 和文档一致性检查；
7. 另行申请生产模型、候选清理、镜像与部署授权。

## 12. 2026-08-02 隔离实施结果

本轮在分支 `codex/model-assisted-admission` 完成 G0–G3 纵向切片，生产容器和生产 namespace
未连接、未修改：

- 211 项非集成测试与 Ruff 全部通过；
- 25 项隔离 integration Gate 全部通过，覆盖统一记忆、API、社区投影、星系视图与迁移；
- 原子准入自检通过，验证确定性 candidate 可被模型 `accept` 幂等晋级；
- Compose production 配置渲染通过；
- 5 个噪声回合（短控制 4 条和“过去了几个小时”）结果为
  `0 fact / 0 episode / 0 review`；
- candidate 技术情节不会进入默认星图，模型 `review` fact 不进入普通对话召回，显式检索仍可追溯；
- 可信工具观测仍可形成技术候选，且在人工确认前不能支撑 active 程序性记忆。

未完成项：未调用真实模型供应商，未执行历史 candidate dry-run/清理，未评估真实金标的 10%
人工比例，也未构建镜像或更新生产。UI/Vault 两类既有集成用例因本轮宿主隔离进程未注入测试
明文密码和 Vault key 而未复跑；本轮代码未修改这两个子域。
