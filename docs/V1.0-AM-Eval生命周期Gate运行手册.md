# Agent Memory for Hermes — AM-Eval v1 生命周期 Gate 运行手册

## 1. 用途与边界

`agent-memory-lifecycle-gold-v1` 将 AM-Eval v1 要求的 20 组生命周期操作从 pytest 实现细节中
抽离为冻结 JSONL 契约，并使用真实 repository、current state、recall、trace 与 purge worker 路径验证。
它是公开合成回归 Gate，不是私有盲测，也不更新正式 AM-Eval 质量分。

运行时必须满足以下边界：

- 只连接 `127.0.0.1`、`localhost` 或 `::1`；
- 数据库名必须以 `am_eval_` 开头，且运行前没有任何 namespace；
- namespace prefix 必须以 `hermes:automated-tests:` 开头；
- 输出必须位于源码仓库外、父目录权限为 `0700` 或更严格，且目标文件不存在；
- 不读取生产数据、不连接生产 API/数据库/namespace，不调用外部模型；
- 每次运行使用新数据库，结束后删除该数据库。

## 2. 冻结数据集

- manifest：`benchmarks/am-eval-v1/datasets/lifecycle-gold-v1/manifest.json`
- case：20 条，development/validation 各 10 条；
- 数据：仅 action、variant 和 invariant，不含记忆正文；
- action 分布：

| 操作 | 数量 | 核心验证 |
| --- | ---: | --- |
| confirm | 2 | candidate 激活、跨 namespace 拒绝 |
| correct | 3 | supersede、证据与 trace 链路、跨 namespace 拒绝 |
| forget | 2 | 状态收敛、召回排除、证据保留、隔离 |
| isolate | 2 | 状态收敛、召回排除、证据保留、隔离 |
| purge | 2 | 精确 ID 二次确认、事实/索引/证据/实体/当前状态零残留 |
| current_resolve | 2 | 当前事实隐藏、乐观锁冲突 |
| current_expire | 2 | namespace 定向及全局到期扫描 |
| entity_merge | 2 | canonical 合并、事实关联保留、隔离 |
| entity_unmerge | 1 | 恢复独立实体与事实关联 |
| entity_split | 2 | 指定事实迁移、跨 namespace 拒绝 |

加载器会复验 manifest 文件 SHA、总数、suite、精确 action 分布、唯一 action/variant、10/10 split、
允许的 invariant 和 `expected.success=true`。任一项不符即拒绝运行。

## 3. 前置条件

1. 准备只绑定 loopback 的隔离 PostgreSQL；
2. 新建空数据库，例如 `am_eval_lifecycle_<run-id>`；
3. 使用当前 revision 对该空库运行 `alembic upgrade head`；
4. 在源码仓库外创建权限为 `0700` 的输出目录；
5. 计算并人工核对 manifest SHA-256。

示例变量中的密码必须从本机受限 secret 文件或进程环境读取，不得写入仓库、命令历史或报告。

## 4. 运行命令

```bash
export AGENT_MEMORY_DATABASE_URL='postgresql://agent_memory:<isolated-password>@127.0.0.1:55438/am_eval_lifecycle_<run-id>'
export AGENT_MEMORY_SERVICE_TOKEN='lifecycle-test-service-token'
export AGENT_MEMORY_UI_SESSION_SECRET='lifecycle-test-session-secret-0000000000000000'

uv run alembic upgrade head

MANIFEST='benchmarks/am-eval-v1/datasets/lifecycle-gold-v1/manifest.json'
MANIFEST_SHA="$(shasum -a 256 "$MANIFEST" | awk '{print $1}')"

uv run agent-memory-run-lifecycle-benchmark \
  "$MANIFEST" \
  --namespace-prefix 'hermes:automated-tests:am-eval-lifecycle-<run-id>' \
  --output '/absolute/private/path/lifecycle-result.json' \
  --confirm-sha256 "$MANIFEST_SHA"
```

成功时标准输出只包含聚合状态、case 数、通过/失败数和输出路径；私有结果文件只保存 case ID、action、
PASS/FAIL、错误类型和 invariant 计数，不保存合成正文、数据库密码或模型数据。

## 5. 通过条件与退出码

- `PASS`：20/20 case 全部通过，进程退出码为 0；
- `FAIL`：任一 action 的实际 invariant 与冻结期望不同，仍完成其余 case，写出聚合结果并以 2 退出；
- 输入、安全边界或文件权限错误：在业务写入前失败并返回非零；
- 每个 case 独立事务，失败 case 回滚，成功 case 提交；数据库不得复用为下一轮运行输入。

不得把公开合成 Gate 的 20/20 结果解释为真实 Hermes 记忆质量、外部模型质量或 blind benchmark 通过。

## 6. 清理与审核

运行后执行：

1. 确认结果文件权限为 `0600`；
2. 确认 `contains_memory_text=false`、`contains_production_data=false`、`external_data_sent=false`；
3. 保存 manifest SHA、system revision、测试命令和聚合计数；
4. 删除本轮 `am_eval_lifecycle_<run-id>` 数据库；
5. 查询确认没有同名前缀数据库残留；
6. review 代码 diff、Ruff、非集成回归和隔离 PostgreSQL Gate 后再提交。
