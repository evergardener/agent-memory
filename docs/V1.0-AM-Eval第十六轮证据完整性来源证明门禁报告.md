## 1. 为什么新增专用数据集与 runner

历史 G01 来自 9 个 redaction 单测，G03 来自一次 active fact SQL 汇总，G09 来自 5 个 preference
evidence 断言。三类结果没有共同的逐项账本，也无法证明持久化事件、事实、检索文档与 trace API 使用
同一 evidence 链。本轮新增 9 条公开合成 evidence-integrity gold，并将证据链收敛为：

```text
frozen synthetic probe
  -> ingest_turn redaction + redaction_findings
  -> active fact + fact_evidence + retrieval document
  -> persisted event/fact/document scan
  -> trace_memory exact event verification
  -> independent aggregate quality report
  -> metadata-only result + sourced attestation
```

输入含假 credential 形态，所以 dataset 声明 `contains_memory_text=true`；runner result 和 attestation
明确为 false，且集成测试扫描结果文件确认没有原 probe 片段。

## 2. 来源化测量

| ID | 原始来源 | 复算方法 |
| --- | --- | --- |
| G01 | 9 case × event/fact/document 三个面 | 有剩余 finding 或 forbidden fragment 的持久化面数 |
| G03 | 9 个 active facts | 没有 fact_evidence link 的数量 |
| G09 | 同 9 个 facts 的 trace | 精确返回唯一 evidence event 的数量 / 9 |

这些是公开合成持久化/追溯 Gate，不代表生产数据已经扫描，也不替代私有 blind construction/citation
质量。G01 结果的样本数为 27 个持久化面，而不是沿用旧报告中的“9 个测试函数”。

## 3. 实现与 fail-closed 回归

1. 新增 `agent-memory-evidence-integrity-gold-v1`，固定 manifest/case SHA、9 个 case ID、finding 类型、
   forbidden fragment、5/4 split 和每 case 三个持久化面。
2. `agent-memory-run-evidence-benchmark` 只允许 loopback `am_eval_` 空库、自动化 namespace、仓库外
   私有输出；真实 ingest path 创建 event 与 redaction findings。
3. 每个 active fact 都绑定本 case event，检索文档使用同一 redacted fixed point；runner 查询实际 link，
   并用 `trace_memory` 核对 exact event ID。
4. runner 用独立 `build_quality_report` 再核对 facts、traceable facts 与 raw sensitive facts，避免单一
   ledger 实现自证。
5. evidence attestation v1 内嵌原结果字节和 SHA，从 case ledger 复算 G01/G03/G09，并绑定
   source/environment、dataset、OCI digest 与平台。

攻击测试覆盖：manifest/case 重写、finding 类型变化、remaining sensitive finding、forbidden fragment、
泄漏面汇总、evidence/trace 布尔值、active/traceable 汇总和正式 artifact 覆盖。任一 ledger 与汇总同步
不一致都会失败关闭。
