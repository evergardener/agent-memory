# Agent Memory for Hermes — AM-Eval v1 隔离模型评测运行手册

- 状态：`EXECUTION_PLAN_GATE_READY / REAL_MODEL_PENDING`
- 适用范围：公开合成数据冒烟、私有脱敏 blind 数据正式质量评测
- 禁止范围：生产数据库、生产 namespace、生产容器、未经授权的生产派生数据

## 1. 两类运行不能混用

| 运行 | 用途 | 数据声明 | 确认口令 | 是否可作为正式分数 |
|---|---|---|---|---|
| 公开合成冒烟 | 验证外部模型、worker、入库、召回和评分链路 | `contains_production_data=false` | `SEND_SYNTHETIC_BENCHMARK_TO_EXTERNAL_MODEL` | 否 |
| 私有 blind 评测 | 测量真实质量 | `contains_production_data=true` | `SEND_REDACTED_PRODUCTION_DERIVED_BENCHMARK_TO_EXTERNAL_MODEL` | 满足 blind/复核要求后可以 |

不同确认口令是强制门禁。公开合成运行的授权不能用于发送生产派生样本。任何含记忆正文的 manifest、
模型输出和失败样本都必须保存在仓库外私有目录，不能提交到 Git。

## 2. 前置条件

1. 新建只绑定 `127.0.0.1` 的 PostgreSQL，数据库名必须以 `am_eval_` 开头；
2. 数据库必须迁移到当前 head，且 `core.namespaces` 为空；
3. 在仓库外 `0700` 私有目录创建权限为 `0600` 或更严格的普通模型 key 文件；不要复用或读取
   生产容器 secret；符号链接、硬链接、空文件和源码仓库内路径都会失败关闭；
4. 固定待测 Git revision、模型名、API base、manifest SHA、调用预算和自动化 namespace；
5. 在仓库外生成 `0600` metadata-only execution plan，人工确认内容与 SHA 后才允许运行；
6. 先运行零网络、零数据库连接 preflight，再迁移一次性数据库并执行正式 runner。

当前计划使用：

```text
model: ocg/qwen3.7-plus
api base: https://9router.evergardenviolet.top/v1
synthetic cases: 24
maximum supplier calls: 24
model retries: 0
automatic backfill: disabled
```

## 3. 生成计划

以下命令不会连接数据库、不会调用模型，也不输出记忆正文。plan 文件绑定 dataset/manifest SHA、
namespace、run ID、system revision/version、模型、API base、24 次调用预算、精确的单 turn 事实提取
上限、零重试、禁止 backfill、完整 turn allowlist 和所需外发确认口令：

当前 plan schema 为 `am-eval-atomic-execution-plan-v4`；其中实际 worker 提取上限、模型超时、
Current/Weather 时间窗口和可信观察工具 allowlist 都必须与环境精确相等，不能把金标中的期望事实数
当作运行上限，也不能在审核后改变行为参数。plan 还绑定当前源码的 Alembic head；正式 runner 连接
隔离库后的第一个检查是只读核对 `alembic_version`，不匹配时不会写入 namespace 或 evidence。

```bash
MANIFEST=benchmarks/am-eval-v1/datasets/atomic-quality-selftest-v1/manifest.json
NAMESPACE=hermes:automated-tests:am-eval-atomic
umask 077
PRIVATE_RUN_DIR="$(mktemp -d /private/tmp/am-eval-real-model.XXXXXX)"
PLAN="$PRIVATE_RUN_DIR/execution-plan.json"
RUN_ID="am-eval-synthetic-$(date -u +%Y%m%dT%H%M%SZ)"
REVISION="$(git rev-parse HEAD)"

uv run agent-memory-plan-atomic-benchmark "$MANIFEST" \
  --output "$PLAN" \
  --namespace "$NAMESPACE" \
  --run-id "$RUN_ID" \
  --system-revision "$REVISION" \
  --system-version "$(tr -d '[:space:]' < VERSION)" \
  --model 'ocg/qwen3.7-plus' \
  --api-base 'https://9router.evergardenviolet.top/v1' \
  --max-model-calls 24 \
  --max-atomic-facts 8 \
  --model-timeout-seconds 30 \
  --current-state-days 7 \
  --weather-state-hours 24 \
  --trusted-observation-tools 'exec,execute_code,health_probe,shell,terminal'
```

标准输出中的 `manifest_sha256` 必须为：

```text
7e5e7f9401fafcf26882cf0d7b4c3518c3f7c39200b1e155a757da0e93686a6e
```

独立计算 `PLAN_SHA="$(shasum -a 256 "$PLAN" | awk '{print $1}')"`，必须与标准输出中的
`plan_sha256` 相同。用 `jq` 审核 plan 的所有 metadata；确认后不得编辑文件。runner 会按确认 SHA
读取同一 inode，逐项复验全部字段，turn allowlist 不允许子集或超集。

## 4. 配置隔离进程

下面仅为变量名示例。真实值只存在当前 shell 或仓库外的权限受限文件：

```bash
export AGENT_MEMORY_DATABASE_URL='postgresql://agent_memory:<isolated-password>@127.0.0.1:55438/am_eval_atomic_<run-id>'
export AGENT_MEMORY_SERVICE_TOKEN='<isolated-test-token-at-least-16-chars>'
export AGENT_MEMORY_UI_SESSION_SECRET='<isolated-test-secret-at-least-32-chars>'
export AGENT_MEMORY_NAMESPACE='hermes:automated-tests:am-eval-atomic'
export AGENT_MEMORY_WORKER_ROLE='model'
export AGENT_MEMORY_MODEL_ENABLED='true'
export AGENT_MEMORY_MODEL_NAME='ocg/qwen3.7-plus'
export AGENT_MEMORY_MODEL_API_BASE='https://9router.evergardenviolet.top/v1'
export AGENT_MEMORY_MODEL_API_KEY=''
export AGENT_MEMORY_MODEL_API_KEY_FILE='<repository-outside-private-path>/am_eval_model_api_key'
export AGENT_MEMORY_MODEL_ALLOW_EXTERNAL_DATA='true'
export AGENT_MEMORY_MODEL_EVALUATION_MODE='true'
export AGENT_MEMORY_MODEL_EVALUATION_PLAN_SHA="$PLAN_SHA"
export AGENT_MEMORY_MODEL_EVALUATION_TURN_ALLOWLIST="$(jq -r '.turn_allowlist_csv' "$PLAN")"
export AGENT_MEMORY_MODEL_MAX_RETRIES='0'
export AGENT_MEMORY_MODEL_AUTO_BACKFILL_ENABLED='false'
export AGENT_MEMORY_MODEL_MAX_ATOMIC_FACTS='8'
export AGENT_MEMORY_MODEL_TIMEOUT_SECONDS='30'
export AGENT_MEMORY_CURRENT_STATE_DAYS='7'
export AGENT_MEMORY_WEATHER_STATE_HOURS='24'
export AGENT_MEMORY_TRUSTED_OBSERVATION_TOOL_ALLOWLIST='exec,execute_code,health_probe,shell,terminal'
```

runner 强制只从 `AGENT_MEMORY_MODEL_API_KEY_FILE` 读取评测凭据；设置
`AGENT_MEMORY_MODEL_API_KEY` 会被拒绝。key 文件只能包含一行无首尾空白的凭据；API base 不允许
内嵌用户名、密码、query 或 fragment，避免凭据进入 execution plan。建议在启动前只检查路径和权限，
不打印正文。preflight 通过受限文件描述符读取并验证 key，正式 runner 将同一个已验证 profile 传给
模型任务，不再由 worker 按路径二次打开 key 文件：

```bash
KEY_DIR='/absolute/repository-outside/path'
KEY_FILE="$KEY_DIR/am_eval_model_api_key"
test -d "$KEY_DIR" && test "$(stat -f '%Lp' "$KEY_DIR")" = '700'
test -f "$KEY_FILE" && test "$(stat -f '%Lp' "$KEY_FILE")" = '600'
test -s "$KEY_FILE"
```

Linux 上可把 `stat -f '%Lp'` 换为 `stat -c '%a'`。不得用 `cat`、`echo` 或调试追踪打印 key。

先运行 preflight。示例即使数据库端口不可达也应通过，因为该步骤只验证配置、文件权限、plan/manifest
绑定和输出目标，不连接数据库或模型，也不写出预测文件：

```bash
uv run agent-memory-preflight-atomic-benchmark "$MANIFEST" \
  --plan "$PLAN" \
  --confirm-plan-sha256 "$PLAN_SHA" \
  --output "$PRIVATE_RUN_DIR/atomic-output.json" \
  --efficiency-output "$PRIVATE_RUN_DIR/efficiency-input.json"
```

`PREFLIGHT_PASS` 只证明运行配置闭合，不构成外发授权。之后创建全新空库，迁移命令也必须指向该
一次性数据库：

```bash
uv run alembic upgrade head
```

## 5. 运行公开合成冒烟

输出目录必须在仓库外且权限不宽于 `0700`；两个输出文件必须事先不存在：

```bash
uv run agent-memory-run-atomic-benchmark "$MANIFEST" \
  --plan "$PLAN" \
  --confirm-plan-sha256 "$PLAN_SHA" \
  --output "$PRIVATE_RUN_DIR/atomic-output.json" \
  --efficiency-output "$PRIVATE_RUN_DIR/efficiency-input.json" \
  --confirm-external-data 'SEND_SYNTHETIC_BENCHMARK_TO_EXTERNAL_MODEL'
```

runner 对每个 case 最多调用供应商一次；即使 worker 将失败任务置为 retry，也会立即终结为 failed，
避免超出 plan 固定的 24 次请求预算。公开外部模型运行还强制绑定官方 24-case dataset ID、manifest
SHA 和 open visibility；任一参数漂移都在数据库写入前失败关闭。最终状态只有全部 24 个模型任务为
done 才是 `COMPLETE`。

任一任务失败时，runner 仍以 0600 权限写出诊断和无正文聚合文件，打印 `status=FAILED`，随后返回
退出码 2；自动化不得把“生成了结果文件”误判为成功。模型超时只保留原始 evidence 和错误审计，
不得形成事实或候选记忆。本地模型端点与外部模型端点的 `external_data_sent` 必须按实际情况记录。

## 6. 评分与留存

```bash
uv run agent-memory-score-atomic-quality \
  "$MANIFEST" "$PRIVATE_RUN_DIR/atomic-output.json" \
  --confirm-plan-sha256 "$PLAN_SHA"

uv run agent-memory-score-efficiency \
  "$PRIVATE_RUN_DIR/efficiency-input.json" \
  --confirm-plan-sha256 "$PLAN_SHA"
```

合成冒烟结果只能证明真实模型链路可执行，不能更新正式 AM-Eval 分数。可提交仓库的内容仅限不含正文的
聚合指标、运行 revision、manifest SHA、execution plan SHA、模型标识、任务终态计数和 Gate 结果。
原始结果使用 `am-eval-atomic-output-v2`，质量结果、效率输入和终端摘要必须携带同一个
`execution_plan_sha256`，否则证据链无效。完成后删除一次性数据库；原始输出按评测证据保留策略处理，
不得移入仓库。

## 7. 私有 blind 正式运行的额外 Gate

- 创建、复核和冻结流程见
  [`V1.0-AM-Eval私有盲测金标工作流.md`](V1.0-AM-Eval私有盲测金标工作流.md)；
- 100–150 条生产派生事实金标和至少 100 个负样本必须先脱敏、逐条人工复核，并保存在私有受限目录；
- development/validation/blind 切分必须在调参前冻结；
- manifest 必须声明 `visibility=private|restricted`、`contains_production_data=true`；
- 必须另行明确授权向指定外部端点发送该私有数据，并使用生产派生专用确认口令；
- 输出只允许发布聚合分数和安全审查后的最小失败类别，不发布原文；
- M22 的生产 shadow 仍需单独授权，不能由本运行隐式获得权限。
