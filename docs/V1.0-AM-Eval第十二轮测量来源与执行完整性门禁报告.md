## 1. 本轮为什么不是“再跑一次合成分数”

第十一轮证明了执行源码身份，但正式聚合器仍可能接受自称来自某 revision/dataset 的数值；失败模型
任务也能留下和成功结果相似的文件，效率分母可脱离 plan 填写，dataset 与输出路径还存在检查后换绑
窗口。因此本轮先封闭测量来源与执行完整性，不调用供应商、不读生产数据，也不重复用 oracle 提高分数。

本轮目标是证明：进入评分器的运行已经完整终态、调用数与 case 一致、数据与 plan 来自同一不可变读取、
评分代码及依赖环境未漂移、每个聚合数值都能回到实际 artifact，且正式 `PASS` 只能来自按 digest 运行的
镜像，而不是任意 checkout 或可移动 tag。

## 2. 已关闭的高风险路径

1. **失败运行被评分**：output v4 增加 `run_status`、`case_count`、`job_statuses` 与
   `model_invocations`。质量评分要求全部 case 为 `done`；失败运行改写为无正文
   `am-eval-atomic-failure-receipt-v1`，`cases=[]`，并保持退出码 2。
2. **伪造效率分母**：isolated efficiency 的成功/失败数逐项等于任务账本，调用预算等于 plan case 数，
   治理分母不超过 `case_count * max_atomic_facts`；不能再用任意大计数制造极低失败率。
3. **hash/read TOCTOU**：manifest、JSONL、plan 与评分输入从同一个安全 fd snapshot 同时计算 SHA 和解析；
   拒绝 symlink、硬链接、读取中 inode/size/time 漂移及单文件超过 64 MiB。
4. **私有输出父目录换绑**：预检保留 `O_DIRECTORY|O_NOFOLLOW` 的 parent fd；写入使用
   `openat + O_EXCL + O_NOFOLLOW`，并复核目录/文件 inode、owner、mode 和 link count。路径被 rename、
   chmod 或替换时失败关闭并通过 held fd 清理。
5. **Settings 二次加载漂移**：preflight 只加载一个 `Settings` 实例，worker 使用同一缓存对象；模型调用
   前后还会复核运行源与环境指纹。
6. **同版本依赖被替换**：environment v1 记录 CPython version/cache tag、平台，以及 agent-memory、
   LiteLLM、OpenAI、Psycopg、Pydantic 等 16 个关键发行包的版本、文件数和实际内容 SHA。
7. **评分输入不能追溯**：质量/效率 CLI 分别强制 `--confirm-output-sha256` 与
   `--confirm-input-sha256`，结果回写 `input_artifact_sha256`；错误确认在读取后、评分前拒绝。
8. **自报正式结果**：formal run v2 要求 exact schema、实际 artifact bytes、单一证据覆盖、当前评分器
   source/environment 一致；完整质量必须是 private blind、真实模型、recommended-product track。
9. **tag 冒充执行身份**：正式评分必须运行在 `image-build-metadata` provenance，并再次确认
   `name@sha256:<manifest-digest>` 与平台。CI 发布 job 公开 digest，验证 job 按 digest 拉取并产出只含
   metadata 的 identity JSONL。

`ghcr.io/...@sha256:<digest>` 拉取和启动；本地源码/单测不能代替该证据。

## 5. 生产与外部数据边界

本轮没有连接生产 API、数据库或 namespace，没有读取生产消息、Vault、真实 API key，也没有调用外部
模型。为了定位可用隔离 PostgreSQL，做过一次只读 Docker 容器清单检查；未读取生产容器配置、日志或
挂载，更没有重启、更新或修改生产容器。所有写入均限于仓库、临时目录和随机隔离数据库。
