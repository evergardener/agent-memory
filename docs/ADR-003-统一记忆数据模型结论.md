# ADR-003：统一记忆数据模型结论

日期：2026-07-26
状态：Accepted for implementation
范围：阶段 F1–F7

## 决策

1. 保留 rc.8 的 evidence、fact、entity、Subject、relation、episode 和 arc 身份。
2. 通过 `0016_unified_memory` 扩展 episode，并新增角色、步骤、时间规则、偏好版本、
   artifact、procedure 及支撑表。
3. 现有 episode 标记为 `origin=legacy_derived`、`episode_type=legacy_derived`；不修改
   evidence、fact、entity 或原有 episode ID。
4. 记录来源与现实参与角色分离。`source_profile` 不能自动生成 episode participant。
5. 日期、步骤、事实句子和摘要不进入 `memory.entities`。
6. 重复时间规则将“日期事实”和 `reminder_policy` 分开，提醒默认关闭。
7. `explicitness=inferred` 的偏好只能是 candidate。
8. active procedure 必须通过应用层验证至少有一个成功 episode 支撑；数据库保存版本、条件、
   步骤、停止条件和权限，但不执行程序。
9. 新能力使用现有 namespace、审计、生命周期和 retrieval 边界；不新建第二套记忆库。

## 兼容与回滚

- 升级只增加字段、表和索引；默认值使旧 API/worker 在忽略新字段时继续读取现有数据。
- downgrade 删除新投影并移除 episode 新字段，不删除旧 episode/fact/evidence。
- 正式启用前必须通过空库、rc.8 fixture 和生产备份只读副本演练。
- 生产 migration、模型启用和数据重建仍分别授权；本 ADR 不提供生产操作授权。

## 被否决的方案

- 为旅行、故障和纪念日分别建立互不兼容的事件表：会复制时间、角色和治理语义。
- 把每个日期、错误、步骤和报告摘要创建为 entity：会污染星图并制造无意义关系。
- 从 `source_profile` 自动建立主体参与关系：会把记录视角误写为现实事实。
- 让程序保存并自动执行旧命令：违反适用性检查、Vault 和外部操作授权边界。
