## 1. Review 发现

第八轮 execution plan v2 记录了金标 case 中的“期望最大事实数”，但 worker 实际截断候选时使用
`AGENT_MEMORY_MODEL_MAX_ATOMIC_FACTS`。preflight 只要求环境上限不低于金标上限，因此同一个已审核
plan 可以在 8、12 或 20 等不同候选上限下运行。

候选上限会直接影响事实 precision、人工治理量和 token 使用。同一 plan 如果允许不同上限，得到的
M01、M02、M22 和 M23 结果不可比较，也不能证明来自同一冻结配置。

## 2. execution plan v3

本轮将 plan 升级为 `am-eval-atomic-execution-plan-v3`，新增并冻结
`model.max_atomic_facts`。运行规则为：

1. plan 创建时必须显式提供 `--max-atomic-facts`；
2. 数值必须是 1–20 的整数，布尔值不能冒充整数；
3. 数值不能小于任一 gold case 的事实数量，防止评测器主动截断正确答案；
4. preflight 要求环境变量与 plan 精确相等，不再接受“只要更大即可”；
5. worker prompt 和候选 validator 使用同一个配置值；
6. plan 与 preflight 摘要都输出该值，便于人工审核。

当前公开合成 shakedown 固定为每 turn 最多 8 条原子事实，模型调用预算仍为 24 次。
