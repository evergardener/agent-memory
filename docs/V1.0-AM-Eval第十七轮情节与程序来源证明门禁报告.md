## 1. 为什么新增专用数据集与 runner

此前 G04、G08、M04、M09–M14 只有分散的解析器、repository 和 unified-memory 测试，缺少共同冻结
case、逐项 ledger 和可由正式 attestation 重算的原始计数。本轮将用户要求的生活经历、纪念日、偏好
演化与技术排障程序统一成以下来源路径：

```text
frozen synthetic temporal / episode / procedure cases
  -> deterministic parser and applicability decisions
  -> isolated real database supersession and lineage scenarios
  -> temporal / episode / procedure / database ledgers
  -> metadata-only result
  -> episode-procedure sourced attestation adapter
```

输入包含合成记忆文本，因此 dataset 声明 `contains_memory_text=true`；runner result 和 attestation 明确为
false。没有使用生产对话、真实人员、真实主机信息或模型输出。

## 3. 实现与 fail-closed 回归

1. 新增 `agent-memory-episode-procedure-gold-v1`，固定 manifest/case SHA、21 个 case ID、11/10 split、
   五类 suite 与三个数据库 invariant 场景。
2. `agent-memory-run-episode-procedure-benchmark` 只允许 loopback `am_eval_` 空库、自动化 namespace 和
   仓库外私有输出；result 只保存 metadata。
3. 时间、情节和程序 ledger 记录实际选择、实体角色、状态与自动应用决定；聚合值必须从 ledger 逐项复算。
4. current/preference supersession 使用真实数据库路径核对旧记录、新记录、反向引用与单一 active 状态。
5. procedure lineage 核对 active procedure、非自动执行、active support episode、support fact、
   fact_evidence 和 exact event ID。
6. episode-procedure attestation v1 内嵌原结果字节与 SHA，从四类 ledger 复算九项测量，并绑定
   source/environment、dataset、OCI digest 与平台。

攻击测试覆盖：冻结文件契约重写、case ID/分母/汇总篡改、profile confusion、实体角色漂移、越权自动
应用、supersession 断链、procedure evidence event 重定向以及非正式 artifact 覆盖。任一 ledger 与
汇总同步不一致都会失败关闭。
